# 多條件影像檢索

## 介紹卡

**研究問題**　搜尋句子有好幾個條件時，影像檢索系統能把每項都符合的圖片排到前面嗎？

**例子**　你想找「紅杯子在盤子的左邊」。紅杯子在盤子右邊的照片只有位置不符。只有紅杯子而沒有盤子的照片則少了另一個物件。好的搜尋結果會把完全符合的照片排在這兩張前面。

**怎麼看數字**　同圖三句排序正確率（COR）要求模型對同一張圖給「全對的描述」最高分、「只描述已確認內容的短句」次高分、「加入錯誤細節的描述」最低分。跨圖檢索則看前 50 名涵蓋多少標註相關圖（Recall@50），以及排名前段有多集中是相關圖（mAP）。mAP 先在每條查詢的相關圖名次計算從榜首到該名次的精確率，再對相關圖及查詢取平均。

**現象**　原同圖測試通過入池門檻，但最強固定索引模型 CS-CLIP 的嚴格三句排序只有 58.15%。新的左右關係面板上，CS-CLIP 對正句和方向顛倒句的判對率是 49.59%。[同圖判準](../killtests/compositional-retrieval/PREREG_headroom.md) · [左右關係測試](../codex/experiments/retrieval-multipositive/PREREG.md)

**訊號**　同圖的完整句勝過半真句達 92.34%。在獨立圖庫用現有 CORE 逐張看圖與句子、重排前 50 名，mAP 增加 15.79 個百分點。把只有兩個物件的短句分數額外加入重排，在新的左右面板未達預設增益。[獨立重排](../codex/experiments/retrieval-rerank/PREREG.md) · [短句對照](../codex/experiments/retrieval-multipositive/PREREG.md)

**改善空間**　左右關係小面板的 CORE 為 87.13% mAP，距同組標註上限 12.87 點。另一個大圖庫固定前 50 名的差距是 19.50 點。31/136 條查詢的前 50 名沒有任何標註正例，要救回這些題得先改進召回。[大圖庫四臂對照](../codex/experiments/retrieval-anchor-rerank/PREREG.md)

## 設計卡

**假設**　若不同索引模型漏掉的相關圖片不同，讓兩個索引共同決定入池圖片，可在同樣 50 次精細重排下提高全庫 mAP。

**資料與對照**　用原大圖庫的 8,191 張圖與 136 條雙物件查詢。基線取 CORE 整句分數的前 50 名，試驗組交錯取 CORE 與 CS-CLIP 的排序，去重後同樣選 50 張。兩組用同一個 CORE 重排器，試驗組另付一次全庫向量搜尋的成本。[召回與重排協議](../codex/experiments/retrieval-recall-budget/PREREG.md)

**主量與門檻**　同一條查詢配對比較全庫 mAP，按原查詢群做區間估計。預先要求 mAP 至少提高 2 個百分點，且 95% 區間下界大於零。

**診斷**　一起看 Recall@50、前 50 名全無正例的查詢數，以及把既有名單內標註正例全部移到前面可得到的 mAP。三項可看出落差出在候選漏找，還是已入池的圖沒有排好。

**下一個決定**　作業 `26806` 已提交。若候選召回與端到端排名都有收益，再到互斥的新圖庫複驗，並計入額外索引的總成本。[提交紀錄](../killtests/SUBMITTED.log)

### 信心、潛力與資源

- **證據信心 4/5**　兩個評估面板都量到可改善的差距，獨立圖庫也量到現有重排的實際收益。
- **研究潛力 4/5**　如果同樣重排成本能找回原先漏掉的相關圖片，且在新圖庫重現，就能提出可實際部署的改進。
- **下一個實驗與資源**　已提交的 `26806` 估計 1 張 H200 跑 8–18 分鐘，約 0.13–0.30 GPU 小時，不含排隊。沿用約 1.3 GiB 的圖庫快取，新輸出小於 256 KiB。新圖庫複驗是後續，還需準備獨立查詢及標註。[資源估算](../codex/experiments/retrieval-recall-budget/PREREG.md) · [硬體實測](../codex/HARDWARE.md)
