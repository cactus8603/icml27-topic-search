## 固定配置

- 沿用原 SD v1.4、提示 E1／N1／B1、CLIP checkpoint、三個套件版本及 32 張一批。採用 `37e6ae9a63cd3035822dccca2acf90ef12efec93` 的規則和五個配置，從該 Git 版本封存來源並核對各檔 SHA-256。
- 每個提示用 CPU 種子半開區間 `[10000,20000)` 生成 10,000 張，共 30,000 張。區間與原 Gate B 及小樣本配對診斷均不重疊。同一種子可在不同提示重用初始雜訊。
- 僅使用小樣本診斷的第二臂。CLIP 的文字、影像特徵與正規化及 scale 指數沿用 FP16，以 FP32 做 scale 乘法、點積及 softmax。關閉 TF32。影像及各筆分數只在記憶體中處理。

## 判讀與保存

完整覆蓋三個提示及所有凍結種子、機率有效時，沿用原閘門的存在判準。只要其中一個提示有至少 1,000 個相異分數，並在 0.5、0.9、0.99、0.999 其中一個門檻取得 100–500 次命中（含端點），本次重跑判為 PASS。完整覆蓋但沒有合格配對則為 FAIL。中斷或缺資料則為 UNTESTABLE。命中以 FP32 分數和同精度的固定門檻比較，等於門檻即命中。 [原門檻配置](../../killtest/configs/criteria.json)

單張 H200、最多兩小時。只寫一份 JSON 至叢集的 `icml/runs/t2irare/gate-b-precision/<job>.json`，先標記 UNTESTABLE，完整核對後以原子寫入替換。內容為各提示的樣本數、相異分數數、最大同分組、各門檻命中及合格門檻，以及作業、版本與配置雜湊。結果用於本次代理閘門重現的獨立審查。
