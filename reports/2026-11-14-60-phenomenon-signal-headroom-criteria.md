## 通用條文 G（貼在各 PREREG 修改紀錄開頭）

> **2026-11-14｜使用者原則變更後、結果前定案，非探索性。** 停損只依三項判定：
> - 現象：問題存在，而且量得到；
> - 訊號：有非零、高於雜訊的可用訊號；
> - 空間：目前最好的方法和上限之間還有距離。
>
> - **G1** 三項都 PASS → 進候選池。任一項 FAIL → 在本 PREREG 的範圍內不進候選池，並寫明是哪一項。其餘情況為灰區：只准一次條文指定的加碼，否則交給使用者。
> - **G2** 「我們第一版方法對最強基線」一律只做描述：照常計算、照常輸出，用來在池內排序，不得拿來改判。
> - **G3** 既有的閘門（程式正確性、重現、雜訊）、正負控制、構造可行性檢查照舊。閘門失敗記「未能測試」，適用 3 個工作天的修復期。
> - **G4** 三項都是與實作無關的量，符合 57 號第 5 節規則 2 的第一種條件，所以 FAIL 可以直接記為「在本範圍內淘汰」，範圍限定語不得省略。
> - **G5** 同一項裡有 m 條擇一路徑時，信賴水準用 Bonferroni 調整。
> - **G6** 結果檔已經產出、但判斷者還沒讀的，照實註記「已存在、判斷者未讀取」。

## 1. biased-gen-cfg

第 1 週的結果檔已經產出，判斷者未讀取。第 1 週的 3 個 run 只算探索性。本條取代 §3 的三態判定、DECISIONS 條文 6 的停點 1，以及條文 9。

### 現象
- 條件：閘門 2 通過，且 (b) 閘門在第 2 週的 15 對中至少 10 對成立。
- 判定：不過就記「未能測試」；修不好則記「可行性停損」。這一項沒有 FAIL 帶。

### 訊號
兩條路徑擇一（m=2），CI 用 97.5%。
- **S-a**：m6 ≤ log 0.8，且 CI 上界 < 0。若負控制未過，改用 Δ = m6 − m1 判定。
- **S-b**：Γ6 ≥ 4，且 log Γ6 − log Γ1 的 CI 下界 > 0。Γ 改為一律計算。
- **PASS**：S-a 或 S-b 成立。
- **FAIL**：以下兩個條件同時成立：
  - m6 的 CI ⊂ (−0.0953, +0.0953)；
  - Γ6 < 2，或 log Γ6 − log Γ1 的 CI 上界 ≤ 0.2231。
- **灰區**：其餘情況，交給使用者。
- 只有 n/K 時鐘成立時，記灰區。

### 空間
- 上限：BP 精確的 CFG 分數。
- 量：在 e† 處計算
  `G3 = Σ[mse_oracle_cfg3(自身訓練輸入) − mse_oracle_cfg3(測試輸入)] ÷ Σ mse_oracle_cfg3(測試輸入)`，
  用 K=6 的 6 個 run 與凍結的 t 遮罩，以區塊為單位 bootstrap 2000 次（seed 0）。
- PASS：G3 ≥ 0.10，且 95% CI 下界 > 0。FAIL：CI 上界 < 0.05。〔推估〕
- **正負號要和 Codex 對齊後再實作。**

### 其他
- 降為描述：(c)(d) 都過、條文 9 的用語表、H∞。
- (d) CIFAR 移出停損，改為進池後的第一步。

## 2. inoculation-lambda

本條取代 §3 的三態判定，以及 §3a L3 的通過條件。

### 現象
- 條件：閘門 2、3 照舊；L1 的 C ≥ 0.75；13 個有防禦的 arm，其漏出全距在至少 2/3 的任務中 ≥ 20pp〔推估〕。
- C 不足時記「未能測試」。全距不足時記「現象 FAIL」。

### 訊號
- 量：step-0 原始 Λ 的合併 ρ。
- **PASS**：合併 ρ ≥ 0.35、CI 下界 > 0、至少 2 個任務的 ρ > 0，而且拿掉任何一個防禦家族後仍 > 0。
- **FAIL**：合併 ρ < 0.20、CI 上界 < 0.35，而且 L3 也沒過。
- **灰區**：沿用原本的唯一加碼。
- 原本的 PASS 線（0.6、0.3、0.4）改記為「強訊號」，只做描述。

### 空間
- 上限：C。
- 目前最好：Grant、Wichers、Tan、PHM 這四個既有預測量中，合併 ρ 的最大值 ρ_exist。
- **PASS**：C − ρ_exist ≥ 0.20，或沒有任何既有預測量覆蓋 ≥ 10/13 個 arm。
- **FAIL**：某個既有預測量覆蓋 ≥ 10/13 個 arm，且 ρ ≥ C − 0.10。
- 其餘為灰區。
- 報告中要照實寫明：這一項近乎由構造保證。

### 其他
- **L3**：保留，作為訊號的第二版本。觸發條件改為「主版本未 PASS 且 C ≥ 0.75」。版本由 L2 機械決定，用 97.5% CI，預算 5 GPU 小時。

## 4. multifidelity-attribution

本條取代 §5 的三個 STOP，以及 §6 的進池功能。

### 現象
- 量：7 個便宜方法中最好者的同軌跡 LDS（k=50、M=200）。
- **PASS**：< 0.80。**FAIL**：≥ 0.80。
- 前提：閘門 2（≥ 0.88）、閘門 3 照舊。

### 訊號
- 量：ρ⊥ = 各查詢 cos(Y_q(I−UUᵀ), C_q(I−UUᵀ)) 的平均，U、B=10、C 都照 §3，以查詢為單位 bootstrap 10,000 次（seed 0）。
- 雜訊對照：M1 的 C_perm 須 |ρ⊥,perm| ≤ 0.05，而且 M1 原條件也要通過，否則記 `INVALID`。
- **PASS**：ρ⊥ ≥ 0.20，且 CI 下界 > 0.10。**FAIL**：CI 上界 < 0.10。其餘為灰區。〔推估〕

### 空間
- 量：H = LDS(Y) − max(LDS(Spell, B=10), LDS(最佳便宜))，用逐查詢配對 bootstrap。

  `H_x = 跨種子 LDS(Y) − 跨種子 LDS(最佳便宜)`。

  - H_x < 0.05 → 灰區，交給使用者。

## 5. rl-sparse-distill

本條取代判準 1 的 PASS 定義、§4 的三態判定，以及 R3 的角色。

### 現象
- 量：閘門 0(c) 原樣；A、B 至少一組合格就算 PASS。
- **FAIL**：(a)(b) 都過，但 A、B 都不符合 (c)。範圍限「1.5B、3000 token」；配對 C 要不要另開，由使用者決定。
- (a)(b) 失敗時記「未能測試」。

### 訊號
- 量 1：rl_replace 的 pass@64 − rl_hf ≥ 2pp，且單側 1.25 百分位 > 0。
- 量 2：pass@1 回收率 = (rl_replace − base) ÷ (rl_hf − base) ≥ 0.5。
- **PASS**：量 1 和量 2 都成立。
- **FAIL**：量 1 的差 < 1pp。
- 其餘為灰區，走 dev 400 加碼。

### 空間
- **H_a**：rl_replace 的 pass@64 − WiSE 前緣值。
- **H_b**：R2 回應層級混合在 π* 處的 pass@64 − 前緣值。

  - λ=1 的端點，用 vLLM 版和 rl_hf 版各算一次，取較小的差。
- 兩者擇一（m=2），單側 α = 0.00625。
- **PASS**：H_a 或 H_b 有一個 ≥ 2.0pp，且單側下界 > 0。
- **FAIL**：H_a、H_b 的點估計都 ≤ 0，而且 99.375 百分位都 < 2.0pp。
- **灰區**：走 dev 400 加碼；加碼後仍分不出時，記「未能測試（檢定力不足）」。

### 其他
