## K3 快篩結論：GO 在程序上成立，但核心主張的證據很薄，不建議照原計畫投 9 GPU-h

**驗證方式**：「親驗」表示我用 `src/k3_analyze.py` 讀原始步驟紀錄重算過（vllm033 的 python，沒有寫入任何 repo 或 runs，腳本在 /tmp/claude-1047/-work-ChihChungHsu-cactus8603-icml27-s2-gated-sink-kv/bd65f9a7-961a-4b8d-adce-42df28fbb74b/scratchpad/k3/k3recalc.py）。「轉述」表示只讀了文件或彙總 JSON，沒有原始檔可以重算。

### 1. 這題主張什麼、GO 靠哪些數字
- **主張**：Qwen2.5-VL-7B 把每張圖的視覺 token 從 4,096 降到 1,024 或 256（做法是降解析度，不是剪枝）。在 KV 池吃緊時，服務容量 λ 可以用「KV×時間面積模型＋事前預測的重算項」事先算出來，而且比只看 prefill 的模型準。
- **觀察值 λ_obs 的定義**：所有請求一次送入，在 queue 非空的飽和區間套 Little's law，λ = N_sys ÷ 平均服務時間 W；W1r 起 N_sys 也算進被 preempt 的請求。
- **模型**：
  - 每請求平均占用 occ = s_prompt + E[o²]/(2E[o])
  - 並行數 N = min(128, u·P/occ)
  - λ = N / (N·(τ_pre + c_pre·κ·occ·pressure) + E[o]·τ_dec(N, KV))
- **GO 依據**（job 25537，`/work/ChihChungHsu/cactus8603/icml/runs/k3-w1r2/25537/full/summary.json` 的 `W1r2_*` 欄位）：
  - P1：mem 池 6 個留出格誤差（MARE）7.8%，門檻 10%。
  - P2：縮 s 留出格 7.2%，prefill-only 19.0%。
  - P3：容量比 13.1×（o=32）／4.9×（o=1,024）。

### 4. 核心數字有沒有量到主張的東西（以下都是新發現，文件裡沒有）
- **留出格一半近乎送分**：
  - Pareto 混合的 E[o] 只有 45.8，很接近校準用的 o=32，這 3 格誤差 1.1、1.6、8.4%。
  - 真正外插的 o=256 三格平均是 **11.9%，不過 10% 門檻**。
  - 模型在校準用的 mem 格上誤差反而有 11.6%（最高 23%），比留出格還差。
  - 12 個 mem 格全部是預測偏高，誤差有系統方向。
- **完全不用模型的內插就一樣準**：在同一 (池, s) 下，把 1/λ 對 E[o] 在 o=32 與 o=1,024 的觀察值之間線性內插，mem 留出 MARE 是 **8.2%**（W1r 上 9.3%），和模型的 7.8% 幾乎相同。在網格內，模型沒有比內插多帶來什麼。
- **P3 由設計保證，而且主要是算力效應**：
  - big 池不受記憶體限制，s=256 對 s=4,096 的容量比仍有 12.2×（o=32）／3.4×（o=1,024）。
  - 真正歸功於 KV 記憶體的部分只有 1.07×（o=32）、1.23×（o=256）、1.46×（o=1,024）。
  - token 減少 16 倍，比值超過 1.5× 本來就幾乎必然。
- **P2 的對照組是刻意偏弱的版本**：prefill-only 模型把 N 固定在 s=4,096 的觀察值（約 17），放到 N=128 的 s=256 格自然差約 45%。只看 mem 池的 s1024_o256，prefill-only 反而比較準（3.7% 對 14.7%）。
- **自由參數 7 個**：τ_dec 3 個、τ_pre 2 個、u、κ，另外 pressure 的函數形式也是自由選擇。
  - u = 1.12 大於 1，「池效率」超過 100%，實際上是吸收 occ 誤設的修正係數。
  - 全部在同一個 job、同一批題目的校準格擬合，留出只換輸出長度 o。
- **「新題目驗證」資訊量很低**：W1r 的係數直接套到 W1r2 資料是 7.7%。換題目只是同分布重測，題目層面的變異本來就小。
- **主張在什麼條件下會是假的，都還沒測過**：開環到達、異質保留數（真剪枝）、自然輸出長度、真實大小的 KV 池（mem 池 65K token，人為設小，H200 預設約 1.7M）、其他模型、其他硬體、模型自己在長輸出的偏差（big 池 o=1,024 誤差 17.7–23.3%）。
- **量測雜訊和門檻同一個量級**：同一格在兩批題目間，完成率差 20%（mem_s256_o256：28.7 對 34.4）；Little's law 與完成率最多差 28%。門檻才 10%。

### 5. 負面或不一致的結果
- AMD W1 判 NO-GO（48.72%／43.41%），之後被改量法推翻。重設是看過資料後才做的。
- W1r 的 P1 不成立（15.1%）。
- W1r2 用原面積模型（不加重算）15.4%，不過門檻。
- 用 n/wall 當觀察值時 15.5%。
- o=256 三格 11.9%，超過門檻。
- 校準 mem 格 o=1,024 誤差 15–23%；big 池 o=1,024 誤差 17.7–23.3%。
- s=4,096 的 o=32 與 o=mix 兩格，在三次跑（AMD、W1r、W1r2）中都是「多餘 prefill 1,695 token、最多 113 個 preempt」，換了題目也一樣。我查了步驟紀錄：一次送入時引擎先收進 128 個請求，接著 preempt 113 個，這是送入方式造成的現象，會灌大 N_sys。
- model runner 有疑義：H200 是 V2，AMD 可能是 V1，W2 計畫裡 V1 和 V2 混用。

### 9. 總評
- **穩固**：
  - 降視覺 token 會大幅提高容量，且隨輸出變長而縮小。兩批題目一致，但多數來自 prefill 算力減少，不是 KV 記憶體。
  - AMD 的 NO-GO 確實有量法錯誤。
- **有跡象但不足**：面積＋重算模型在網格內 7.8%，但有三個問題：
  - 真正外插的 o=256 是 11.9%。
  - 不用模型的內插就有 8.2%。
  - 結論隨觀察量的量法在 5.8–15.5% 之間擺動。
- **沒有支持**：
  - 開環或真實負載下的可預測性、真剪枝、品質代價、第二個模型、真實大小的 KV 池。
  - KV 記憶體是收益主因：big 池顯示多數收益來自算力。
  - 新穎性：Gate 0 一直沒做。

**結論**：GO 在程序上成立（W1r2 是預先註冊、判定時用新題目），但實質上站不住。過門檻靠的是近乎送分的 omix 格，模型也沒有勝過零參數內插，P3 由設計保證。建議先完成 Gate 0 的讀原文與撞題重查，並把留出切分改成只看外插格、加入內插基線，重算現有資料，不需要 GPU。這些過了再決定要不要投 9 GPU-h。
