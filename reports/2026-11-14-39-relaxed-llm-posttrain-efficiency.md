## 候選 1：把「RL 只改少數決策」變成單一模型

**一句話題目**：RLVR 的增益只落在少數決策位置，據此訓練出單一模型，在 pass@1 接近 RL 模型的同時保住 base 模型的 pass@k。

**研究問題**

1. 2610.24663 的雙模型混合解碼同時有高 pass@1 與高 pass@k，但要兩個模型各跑一次。能否把這個混合策略變成一個模型？
2. 2610.39295 的理論說 pass@1 增益必然付 pass@k 代價。混合解碼看起來是反例。理論的哪個假設在 token 稀疏的更新下不成立？
3. 訓練時就把更新限制在決策位置（其餘位置貼住 base），能不能直接得到同樣的模型，不需要先有 RL 模型？

**可當貢獻的切入角度**

- 蒸餾版：以混合策略當教師做 on-policy 蒸餾。目標分布在非決策位置等於 base，在決策位置等於 RL 模型。這一步不需要重跑 RL。
- 訓練版（gated GRPO）：policy gradient 只作用在「目前策略 greedy 與 base 不同」或 base 低信心的位置，其餘位置加對 base 的 KL。
- 分析：在同一組模型上畫出 pass@1 對 pass@k 的前緣，比較權重內插、KL 正則、選擇性 KL、重播、混合解碼與本方法，並對照 2610.39295 預測的前緣。
- 機制：決策位置能否只用 base 的訊號預測。原論文附錄說 base 信心「已經能排序」這些位置，但沒報準確率【全文前段】。

**最接近的工作與區隔**

- 2610.24663（What RL Brings to Reasoning）：現象來源。只做診斷，需要兩個模型，作者自己列的限制是「等次數而非等算力」【全文前段】。
- SCOPE（ACL 2026 Findings，2026.findings-acl.641）：只對約 5% 的 token 加 KL，宣稱 pass@1 與 pass@k 都進步【搜尋摘要】。**這是最近的對手**，同作者另有 FRACT。區隔：SCOPE 是「挑少數 token 加限制」，本題是「只放少數 token 自由」，而且有混合解碼當明確的目標分布。這個區隔夠不夠，要讀 SCOPE 全文才知道，ACL Anthology 頁面這次連線失敗沒讀到。
- 2603.22117（Direction of RLVR Updates，ICLR 2026）：用 Δlog p 的方向找關鍵更新，並做訓練時重新加權【摘要頁】。區隔：它的目標是 pass@1，沒有處理多樣性。
- TAR 2610.24236：重播 base 的多樣正確解【摘要頁】。可當基線。
- 2610.39295：理論對照。
- 權重內插方向已有 2504.10478（SFT 的 WiSE-FT）與 2605.28751（程式碼 RL 的外插平均）【搜尋摘要】，要當基線而不是當貢獻。
- 2608.27351：ES 的 pass@k 高於 GRPO，先 GRPO 後 ES 的排程已有人做【全文前段】。

**基準與基線**

- 模型：Qwen3-1.7B-Base、Qwen3-4B-Base（原論文用 4B、8B 與 Llama-3.2-3B，RL 用 verl 的 GRPO 加 DAPO-Math-17k）。
- 評測：MATH-500、AIME 120 題；pass@1 與 pass@k（k 到 64 或 256）。
- 基線：GRPO、DAPO、GRPO 加全域 KL、SCOPE、TAR、DPH-RL 2509.07430、權重內插、rl-replace（當上限）。

**前兩週計畫**

第 1 週（約 250–350 GPU 小時【推估】）
- 取得 base 與 RL 模型配對。原論文沒說 checkpoint 是否公開【全文前段】，要先看程式庫；沒有就自己用 GRPO 訓 1.7B（約 60–100 GPU 小時【推估】）與 4B（約 150–250 GPU 小時【推估】）。
- 重現稀疏替換：決策位置比例、pass@1 增益回收率、pass@64。原論文報的成本是每個 AIME 年度 7.3–7.9 GPU 小時【全文前段】，GPU 型號沒確認。
- 順手跑權重內插的 λ 掃描，當最便宜的前緣基線。

第 2 週（約 150–250 GPU 小時【推估】）
- 混合策略的 on-policy 蒸餾（LoRA 與全參數各一），量 pass@1 與 pass@64。
- gated GRPO 在 1.7B 上跑一個先導實驗。

停損判準（事先寫定）
- 稀疏替換在自己的配對上，用不超過 10% 的位置拿不回 70% 的 pass@1 增益：三個相關候選一起停。
- 蒸餾後的單一模型保不住 70% 的 pass@1 增益，或 pass@64 沒有比 RL 模型高出種子雜訊：停蒸餾線。
- 在相同 pass@1 下，pass@64 贏不過權重內插與全域 KL 這兩個最便宜的基線：停。

**主要風險**

- 多樣性保留這一串非常擠，容易被看成又一個變體。論文必須以「混合解碼這個明確目標」與「和理論的對照」當主軸。
- 2610.24663 的作者很可能自己做後續。
- pass@k 的差距在小 k 很小：2608.27351 的表中各方法 pass@16、pass@32 只差 1–3 點【全文前段】。差距主要在 k=256 才明顯，評測成本高。
- 原論文自己說跑與跑之間變異大。

**信心**：中。

## 候選 2：量化會不會把 RL 的增量抹掉

**一句話題目**：定義並量測「RL 增量保留率」，說明低位元量化優先破壞的是 RL 改過的少數決策，並用決策感知校準或稀疏全精度覆蓋補回來。

**研究問題**

1. RL 的權重更新很稀疏、幅度小（ICML 2026 oral 2602.07729 報告 SGD 只更新 0.02%–0.46% 的參數，此數字出自先前回報 30，摘要等級）。量化後 Q(W_RL) 與 Q(W_base) 有多少權重其實相同？
2. 量化後的準確率損失，有多少是 base 能力的損失，有多少是 RL 增量的損失？
3. 量化模型的 token 是不是在決策位置優先「退回」base 的選擇？這能不能解釋推理變長（2606.25519）與迴圈？

**可當貢獻的切入角度**

- 新指標：RL 增量保留率 =（量化後 RL 模型 − 量化後 base）÷（全精度 RL 模型 − 全精度 base），以及決策位置與非決策位置的翻轉率。
- 方法甲：決策感知校準。逐層重建（GPTQ 類）的 Hessian 依 token 加權，權重來自 base 與 RL 模型的 |Δlog p|。只動校準，不需訓練。
- 方法乙：稀疏全精度覆蓋。base 量化一次，RL 的 Δ 取 top-k 以全精度稀疏儲存。附帶好處是一個量化 base 可掛多個 RL 專長。
- 把推理變長納入指標，而不只看準確率。

**最接近的工作與區隔**

- 2511.15694（NeurIPS 2025 workshop）：量化感知的 RL 訓練傷害學習，RL 之後再做 PTQ 或 QLoRA 較好【搜尋摘要】。它比較的是流程順序，沒有分解增量，也沒有 token 層級的機制。
- RECAP 2610.15259：在模型實際讀到的長歷史上校準，W4A4KV4 下 R1-Distill-Qwen-1.5B 的 MATH500 多 13.3 點、Qwen3-4B 的 AIME-120 多 15.8 點【摘要頁】。同屬「校準該看什麼」這條線，它看的是歷史，本題看的是決策 token。
- 2606.25519：INT4、INT3 準確率大致不變但推理 token 變多【摘要頁】。只描述現象，建議用 QAT。
- OnQ 2610.29378、2609.26708：2–3 位元用 on-policy 蒸餾救回。這是需要訓練的上限參考。
- BitDelta 2402.10193【推估，憑記憶】：全精度 base 加 1 位元 delta。方法乙是反過來的配置。

**基準與基線**

- 模型配對與候選 1 相同；另加公開的蒸餾式推理模型（R1-Distill 系列）對照「RL 式比蒸餾式更不耐量化」這個說法。該說法只在搜尋摘要看到，2504.04823 的摘要頁沒有這句，**未確認**。
- 位元：W4、W3（W4A16 已被報告為無損，重點在 W3 與推理長度）。
- 基線：RTN、GPTQ、AWQ、RECAP；OnQ 當上限。
- 評測：MATH-500、AIME、LiveCodeBench；準確率、保留率、推理 token 數。

**前兩週計畫**

第 1 週（CPU 加約 40–60 GPU 小時【推估】）
- 純 CPU：算 RTN W4、W3 下 Q(W_RL) 與 Q(W_base) 不同的權重比例。十分鐘內有答案。
- GPTQ／AWQ 量化 base 與 RL 模型，算保留率。
- 在全精度 RL 模型的軌跡上做 teacher forcing，比較決策位置與非決策位置的 argmax 翻轉率。

第 2 週（約 80–120 GPU 小時【推估】）
- 實作決策加權的 GPTQ 與稀疏覆蓋，對 RECAP 比較。

停損判準
- W3 標準 PTQ 的保留率高於 85%（代表沒有問題可解）：停。
- 決策位置翻轉率不到非決策位置的 2 倍（機制不成立）：停。
- 兩個方法都補不回失去增量的一半：停。

**主要風險**

- W4 已無損，可做的空間只剩 W3 與推理長度，題目可能偏小。
- 先前回報 31 的結論仍然成立：2 位元時同記憶體輸給較小的模型，且核心空缺已被三篇填掉。本題刻意不做 2 位元。
- GPTQ 類方法的誤差補償可能已經間接保住決策 token。

**信心**：低到中。優點是最便宜，第一天就有第一個數字。

## 候選 3：便宜的 base 與 RL 混合解碼

**一句話題目**：只在預測出的決策位置查詢 RL 模型，並共用 KV cache，把混合解碼的成本從 2 倍壓到接近 1 倍，在等算力下做測試時擴充。

**研究問題**

1. 只用 base 的訊號（熵、margin、hidden state 探針）標出決策位置，在標記率 15% 以下能回收多少增益？
2. RL 模型能不能直接讀 base 的 KV cache 只算那一個 token？
3. 在相同算力下，混合解碼的多數決與 best-of-N 是否贏過只用 RL 模型？

**可當貢獻的切入角度**

- 補上 2610.24663 自己列的限制：等算力比較與學習式的位置選擇（原文說這兩項都沒做）【全文前段】。
- 跨 checkpoint 的 KV 共用：base 與 RL 模型的差是稀疏小更新。可以直接沿用先前 R3 題目的量測方法（舊 KV 在權重更新後的偏移）。
- 一個量化 base 加多個 RL 專長在 token 層級切換，當成模型合併以外的選項。RLVR 模型合併已有 2606.18521、NeurIPS 2026 的 spectral alignment 一篇、2602.12566。

**最接近的工作與區隔**

- 2610.24663：同上。
- R2R 2505.21600【推估，憑記憶】：小模型與大模型之間的 token 層級路由。區隔：本題是同架構、權重幾乎相同的兩個模型，可以共用 KV，目的包含保住多樣性。
- 2611.05345（Adversarial Speculative Reasoning）：訓練 draft 在關鍵推理點被拒絕【摘要頁等級的列表轉述】。要讀全文確認重疊程度。
- 2603.22117 的測試時外插：同樣是用 base 與 RL 兩個模型的 logits，但每一步都要兩個模型。

**基準與基線**

與候選 1 相同的模型與評測；基線為只用 RL 模型、只用 base、rl-replace（2 倍成本）、權重內插的 checkpoint 組合（2605.28751 的做法）。指標是固定總 token 運算量下的多數決準確率與 pass@k。

**前兩週計畫**（與候選 1 共用第 1 週的配對與重現）

- 第 1 週追加（約 30 GPU 小時【推估】）：位置預測的 precision–recall 曲線；RL 模型讀 base 的 KV 與讀自己的 KV，在決策位置的 top-1 一致率。
- 第 2 週（約 120–200 GPU 小時【推估】）：實作 gated 混合解碼，做等算力比較。

停損判準
- 標記率 15% 以下回收不到 rl-replace 的 80%：停。
- KV 共用的一致率低於 95%：改成不共用 KV 的版本，成本優勢會縮小。
- 等算力下多數決沒有贏過只用 RL 模型：停。這一條最可能不過。

**主要風險**

- 「為什麼不直接用 RL 模型」是最強的反駁。pass@k 的優勢要有驗證器才用得上，多數決未必受益。
- 原論文說限制在預測位置做 MCMC 沒有幫助（9.84 對 10.00），並說難處在「選對 token」【全文前段】。本題在標記位置直接取 RL 模型的 token，情況不同，但位置預測的召回率仍是關鍵。

**信心**：低到中。

## 候選 4（獨立備案）：零階 RLVR 的 rollout 耦合

**一句話題目**：讓零階／演化策略在真正 on-policy 的 RLVR 上可用，方法是把兩個擾動策略的自回歸取樣用共同亂數耦合，並延伸到無法反向傳播的 INT4 模型。

**研究問題**

ZO-BOLT 2611.03260 指出 on-policy 零階 RL 因為兩次評估的資料不相同，雜訊被放大 1/μ²，並改用資料相同的 SFT 式目標繞過【摘要頁】。全文說離散自回歸生成「沒有辦法在不違反 on-policy 邊際分布的前提下跨參數重用相同軌跡」【全文前段，小模型轉述，需讀原文確認措辭】。Gumbel-max 共同亂數耦合在定義上保持每個策略各自的邊際分布，所以這句話看起來可以反駁。問題是耦合在長生成下還剩多少。

**可當貢獻的切入角度**

- 耦合估計量的變異數分析（我的猜想是 1/μ² 可降到 1/μ，**未證明**）。
- 長序列下維持耦合的做法（分歧後重新同步、分段評估）。
- 在 INT4 模型上直接做 RLVR，與 MobileSpec 的 FuRA-S 比較。

**最接近的工作與區隔**

- ZO-BOLT 2611.03260：Qwen2.5-1.5B 的 GSM8K 由 52.24 到 63.78、MATH 由 29.82 到 32.84；7B 的 MATH 由 50.30 到 58.00（一階版本 61.42）；1.5B 尖峰記憶體 4,201 MB 對一階的 10,363 MB【全文前段】。
- 2608.27351：**已經試過亂數耦合**。主文說雙點對偶 ES 沒有優勢，原因是「早期 token 分歧削弱配對共變」；附錄有 Randomness Coupling 診斷，結論是 SST-2 有變異數下降、GSM8K 的重新生成獎勵不穩定【全文前段，附錄內容被截斷沒讀到】。這直接削弱本題。
- ES 2509.24372：適應度評估用 greedy 解碼【全文前段】，等於耦合的確定性特例。
- MobileSpec 2611.04797：只用前向傳遞，可調 INT4 模型，專家模組 1–5 MB【摘要頁】。

**前兩週計畫**（約 60–100 GPU 小時【推估】，全是前向運算）

- 第 1 週：讀完 2608.27351 附錄 E 與 ZO-BOLT 後半。在 Qwen2.5-1.5B 與 GSM8K 上量獨立取樣、共同種子、Gumbel 耦合三種設定的配對共變與估計量變異數，對生成長度作圖。
- 第 2 週：如果耦合在長度超過約 200 token 後仍有效，接上 ZO-GRPO 跑端到端。

停損判準：Gumbel 耦合在 GSM8K 上的變異數比沒有明顯優於 2608.27351 報告的共同種子結果，就停。

**主要風險**：已有論文報告耦合在長生成上弱；零階方法在難題上落後一階方法（ZO-BOLT 自己說差距隨難度擴大）；審稿人會問為什麼要零階。

**信心**：低。列入是因為它不依賴候選 1–3 的共同前提。

## 為什麼候選 1 排第一

1. 它落在 ICML 最大的子領域，而且同時有方法與分析，接得上一個月內剛出現的理論（2610.39295）與現象（2610.24663）。目前沒有人把兩者放在一起檢驗。
2. 有明確、可量化的目標：混合解碼已經示範了「pass@1 接近 RL、pass@k 高於 RL」這個點存在，題目是用一個模型達到它。這不是找不存在的上限。
3. 第一週的重現是便宜又明確的 GO／NO-GO。
4. 失敗時有退路：蒸餾線不行還有訓練線；兩條都不行，前緣比較與理論對照仍是有正面結論的分析，但那樣比較接近 workshop 等級，要誠實看待。
5. 同一份第一週的投入同時為候選 2 與 3 取得資料。

候選 2 排第二是因為最便宜、和 efficient AI 的銜接最直接，但可做空間較窄。候選 3 的實用性論證最弱。
