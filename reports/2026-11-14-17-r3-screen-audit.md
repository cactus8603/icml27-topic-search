### 1. 主張與 GO 依據
- **主張**：非同步 RL 換權重時，進行中的請求會沿用舊 KV。這個偏移能用「同一段前綴在新舊權重下 K/V 的相對變化 dKV」預測，而且比只看落後步數（lag）準。
- **核心量**：
  - stale KL 是 KL(nn‖no)：新權重配新 KV，對上新權重配舊 KV，逐位置算完整詞表的 KL 再取平均。
  - dKV = √((dK²+dV²)/2)，dK、dV 是 K、V 的相對 Frobenius 差，取層平均。
  - 預測模型是 log KL = a + b·log dKV + d·log Lp，在校準 stream A1、A2 上擬合，在留出 stream B1、B2 的格平均上算相對誤差。
- **GO 依據**（job 25474）〔驗〕：
  - P1：留出 drift 誤差中位數 19.87%，門檻 20%。
  - P2：lag 基線 55.5%。
  - V1 = 0.634，V2 = 0.917。

### 4. 量的是不是主張的東西
- **dKV 對 stale KL 近乎同義反覆**：
  - stale KL 唯一的來源就是前綴 KV 的差，所以兩者的相關係數高到幾乎是必然：全部 stream 0.96，校準 0.94〔驗〕。
  - 更大的問題是實用性。要算 dKV，就得先用新權重把前綴 prefill 一次，而這正是「重算」本身的成本，所以逐請求的 dKV 拿來決定要不要重算是循環的。W2 只把「probe」（便宜的代用指標）列為「只記錄」，P1／P2 仍然用逐請求的 dKV 判定。
- **P2 幾乎被設計保證會成立**：校準集同一個 lag 混了兩種 lr，只看 lag 的模型不可能解釋 lr 造成的差異，必輸。W2 校準也是兩種 lr（G1 1e-6、G2 3e-6），同樣的結構會再出現一次。
- **免費的權重範數 dW 基線**（W1r 有記錄 `dW_kv`，但沒拿來當基線；重算見 [`recompute.py`](/tmp/claude-1047/-work-ChihChungHsu-cactus8603-icml27-s2-gated-sink-kv/bd65f9a7-961a-4b8d-adce-42df28fbb74b/scratchpad/r3/recompute.py)）〔驗〕：

  - 同一格內 16 條序列的 stale KL 變異係數中位數 26%，最高 38%〔驗〕。
  - P1 的邊際只有 0.13 個百分點，B1 上 drift 與 lr·lag 也只差 3 個百分點，都落在雜訊內。bootstrap 中 drift 在 B1 勝過 lr·lag 的比例是 93%。

  - 真正有資訊量的只有 A1、B0 的 512、2,048 四格，對了 2 格；B0 預測 lag 4，實際是 lag 8。

### 8. W2 要跑什麼、成本、程式是否就緒
- **內容**：
  - Gate 0 job：8,192 底線診斷、用新底線重判 W1r、V0 實測 vLLM keep 模式。
  - 正式：TRL GRPO 四個 stream（G1–G3 全參數、L1 LoRA），72 步，lag 到 32，四個量測領域，共 4,032 組量測。
- **成本**：上限 13.5 GPU-h，正式部分估 2.8–6.8 GPU-h，4 張 H200 平行。
- **程式就緒度**：
  - 程式與 CPU 自測已經 commit。
  - TRL／PEFT 還沒安裝：`envs/r3w2-pylib` 不存在〔驗〕，安裝需要使用者同意從 PyPI 下載。
  - TRL 1.17.1 宣告支援 vLLM < 0.33，環境是 0.33.0，可能要走退路。
  - 結論：Gate 0 可以直接送，正式跑還不行。
- **設計上的問題**：
  - Gate 0 的「重判 W1r」只改底線，而底線只影響 P0 和 V2，碰不到 P1 的薄邊際，保護作用有限。
  - P2 仍然被設計保證會成立。
  - W1 已經顯示 lr 2e-6 在 lag ≤ 8 不越界，所以 G1（lr 1e-6）讓 P0 不成立、直接 NO-GO 的風險很高。

### 9. 總評
- **穩固**：
  - 小學習率的 SFT 下，lag ≤ 4–8 時偏移落在數值底線內，AMD 與 H200 方向一致。
  - 大學習率時偏移明顯越界。
  - 量測與分析程式可以否證，分析程式也在結果出來前就固定了。
- **有跡象但不足**：
  - dKV 帶有權重範數以外、與內容相關的資訊，但只靠一個有混淆的 stream（B2）。
  - P1 的 19.9% 恰好壓線，bootstrap 下過關機率只有 32%，去掉 8,192 格就不成立。
- **沒有支持**：
  - dKV 比免費的權重範數更準：同領域的 B1、B0 上都是 dW 贏。
  - drift 勝過 lag 是實質發現：這是設計保證的結果。
  - 在真實 RL 學習率、LoRA、目標 runtime 下成立。
  - 逐請求 dKV 有實用價值：算它的成本等於重算。
  - 這題沒有撞題：Gate 0 從未完成。

**一句話結論**：目前的 GO 只是依規則技術性過關，不是穩固的證據。在投入 W2 的 GPU 之前，應該先做零 GPU 成本的兩件事：完成 PipelineRL 圖 7 的閱讀與撞題重查，並把 dW 與 probe 基線升為判定條件。至多先送 Gate 0（≤ 1.5 GPU-h）。
