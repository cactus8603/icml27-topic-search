# 多條件檢索 P1 FAIL 的深入判讀（Fable，2026-11-14）

**來源**：Fable 子代理回報，經主對話整理後轉存，結論與數字未改。
**起因**：使用者質疑「會不會根本是設計上有問題」。
**範圍**：Fable 只讀了 46 號報告、PREREG、VERDICT、REVIEW 和 aggregate.md。報告中提到的前人工作都是 Fable 憑記憶判斷，沒有查證。

## 總結
- **P1 FAIL 只否證了一種實作。** 這次在程序上成立的 FAIL，否證的是「去脈絡單元的邊際 PMI 加總」這個做法，核心機制和整個方向都沒有測到。
- **原本的淘汰建議是過度推論。** 先前寫的「題目假設不成立、建議淘汰」，推論超出了實驗能支持的範圍。
- **建議做第二探針。** 把邊際 PMI 換成條件 PMI，其餘設定不變，成本預估不到 1 GPU 小時。
- **第二探針也 FAIL 才淘汰。** 淘汰理由要寫成「我們沒有可區隔的切入點」，而不是「假設為假」。
- **ICML 價值評為中偏低。** 要升到「中」，需要探針 PASS，而且「邊際對條件證據」能寫成定理。這條線的上限是「中」，達不到中偏高。

## 1. 被否證的是什麼

| 層級 | 判定 | 理由 |
|---|---|---|
| (a) 實作：去脈絡單詞、邊際 PMI、0 門檻、免訓練 | 已否證 | COR 的上限是 P(PMI(d−)<0)：CLIP 為 40.5%，低於門檻 45；CS-CLIP 為 35.8%，低於 holistic 的 58.2。 |
| (b) 機制：逐條件證據聚合比 holistic 更能反映錯誤細節 | 未被測試 | anchor 項被抵銷，等於假設各細節條件獨立；Half-Truths 的錯誤細節正是針對這個假設設計的。 |
| (c) 方向：多條件檢索中細節錯誤的處理 | 未被否證 | E2 沒跑，CORE reranker 沒量，也沒做訓練版。 |

**真正壞掉的是條件獨立假設，不是「錯誤細節該降分」。**
- 依鏈式法則，細節的正確增量是條件 PMI(d; I | anchor)，但實作用的是邊際 PMI(d; I)。
- 合理的錯誤細節（例如把 train 換成 bus）與 anchor 高度相關，所以邊際 PMI 會偏正：PMI(d−) 的中位數在 CLIP 是 +0.66，在 CS-CLIP 是 +1.23。
- 這個限制 PREREG §7 第 3 點事先就寫了。

**COR 這個指標本身沒有問題，問題在停損實驗怎麼用它。**
- COR 對加法式評分器會退化成符號檢定，同時考「相對鑑別力」和「零點校準」兩件事，這次是死在零點校準。
- 門檻 45 比構造上的上限 40.5 還高，凍結前沒有做上限檢查。
- 在文字找影像的方向，文字端的校準常數會互相抵銷，所以 llr_sum 和 unit_sum 排出的順序完全一樣。

**69.5%／81.5% 還不能當作支持證據**，因為缺少 holistic 在相同情境下的成對正確率可以對照。
- 目前唯一對機制有利的數字是 CLIP 的 entity 類：LLR 38.2，holistic 26.0。
- relation 類反而變差：LLR 8.2，holistic 11.8。原因是細節抽取時被截斷。

## 2. 替代實作

| 做法 | 先前工作 | 能否撐起一篇 ICML | 成本 |
|---|---|---|---|
| A. 條件 PMI（雙塔）：s̃(T) = τ·s(I,T) − log mean_pool exp(τ·s(I',T)) | 形式上近似 inverted softmax、dual softmax、QB-Norm 這類 hubness 正規化（憑記憶）；有沒有人用在 half-truth 上，需要查 | 單獨撐不起來，要配公理和定理 | 不到 0.5 GPU 小時 |
| B. 生成式 VLM：log p(d\|I,anchor) − log p(d\|anchor) | 近似 VisualGPTScore；也和 TIFA、DSG、VQAScore、CORE 重疊（憑記憶） | 撐不起來，只能當上限或教師模型 | 1–3 GPU 小時 |
| C. 學習門檻或校準 | 一般性技巧 | 撐不起來，最後會收斂成 A 或 B | 約 0 |
| D. 細節單元保留修飾語 | 是 A 的中間版本 | 只能當消融實驗 | 約 0 |
| E. 反事實替代集：用 LLM 產生替代細節，再做 softmax | 可能較新，需要查 | 中偏低；替代集必須在看不到 d+／d− 的情況下產生 | 約 1 GPU 小時加上 LLM 推論 |
| F. 訓練版：把 A 或 B 的增量蒸餾回單向量 | 已被 CS-CLIP、CORE、GradCIR 佔位 | 唯一可能到「中」的路線 | 8–20 GPU 小時 |

**建議**：只用 A 當第二探針，B 只附帶做診斷，E 和 F 等 A 通過後再考慮。

## 3. 第二探針的設計

- **規模**：純推論，預估不到 1 GPU 小時，上限 3 小時。
- **評分**：用 A 的 s̃(T)。影像池沿用 PREREG §3（HT 的 1379 張唯一影像），資料、模型、bootstrap 設定都不變。
- **唯一主指標**：CS-CLIP 在 COCO(Qwen)（n=509）上，COR(s̃) − COR(holistic) 的配對差。
  - PASS：點估計 ≥ +5pp，且單尾 α=0.025 的下界 > 0。
  - FAIL：上界 < +5pp。
  - 其他情況算灰區，交給使用者決定，不加碼。
- **構造閘門**（任一失敗就記為「未能測試」）：
  - 正控制：把 d− 換成從別列隨機取的細節，COR 要 ≥ 70%。
  - 負控制：把影像打亂，COR 要 ≤ 15%。
  - 上限檢查：成對正確率 P(s̃(A+)>s̃(A−)) 要高於約 63%。低於這個值就直接記為構造不可行。
- **只描述、不參與判定**：
  - CLIP B/32 上的同一個指標；
  - 影像池換成 COCO val2017 共 5000 張時的敏感度；
  - B 做法（VLM 條件 LLR）的 COR，若 ≥ 90% 就觸發 46 號報告的旗標。
- **聲明**：這組資料已經看過一次結果，所以這次要標記為「停損後第二探針」，凍結後只跑一次。
- **跑之前先在 CPU 上補算兩個數**：
  - holistic 的成對正確率；
  - 邊際 PMI 在最佳全域門檻下的 COR 上限。
- **若第二探針也 FAIL**：可以淘汰，理由寫成「免訓練、固定索引的雙塔證據聚合，邊際和條件兩種形式都贏不了 CS-CLIP；剩下的路線已被 CS-CLIP 和 CORE 佔住，沒有可區隔的切入點」。但如果是正控制沒過，就記為「未能測試」。

## 4. ICML 價值
- **評級**：中偏低，信心中等。要升到「中」，需要探針 PASS，加上「邊際對條件證據」的定理（說明何時違反單調公理）。
- **扣分理由**：
  - 量尺被 Half-Truths 佔住，訓練式解法被 CS-CLIP 佔住，分級蒸餾被 CORE 和 GradCIR 佔住。
  - A 做法看起來很像已知的 hubness 正規化。
  - 方法的適用範圍比題目名稱窄。
  - 還沒量 CORE reranker 是否已經解決這個問題。
- **優先順序**：排在其他已有正面訊號的題目之後。探針之前，投入不要超過一天。

## 5. 通用判讀規則（適用所有停損實驗）
1. **三層判定必填**：每份 VERDICT 都要分別對實作、機制、方向寫明「已否證／未測試／有支持」。FAIL 預設只算到實作層。
2. **升級成「題目淘汰」要有額外條件**，至少滿足下列其一：
   - 一個與實作無關的上限或 oracle 測試失敗；
   - 兩個有原則且彼此不同的實作都失敗，而且逐條寫出剩下的切入點為什麼已經關閉。
3. **凍結前加「構造可行性」閘門**：先算出主指標在這個構造下的上限，門檻不得高於上限；另外要有一個正控制。正控制沒過就記為「未能測試」。
4. **PREREG 要列「代理落差」**：寫明便宜實作相對於題目主張簡化了哪些地方。如果失敗原因正好落在列出的落差上，就判為實作失敗，並觸發一次事先限定預算的第二探針，只限一次。
5. **主指標要拆開回報，用語要分清楚**：說明是哪個成分失敗，並附上 holistic 對照。用語上區分「此實作停損」和「題目淘汰」，不可以把前者轉述成後者。
