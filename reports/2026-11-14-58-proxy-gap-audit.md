## 1. biased-gen-cfg（兩個時鐘）
1. **代理落差**
   - 主指標只測「CFG 讓起點提早」。題目的另一半主張是「CFG 以 (1+w) 放大樣本特定成分」，PREREG 把幅度列為次要（已列），但沒有寫明 FAIL 不涵蓋幅度主張（未列）。
   - 只比較 w=3 與 w=0 一個劑量，w=1 有算但沒用上（未列）。
   - 用分數層級距離，不是原作主證據的樣本層級距離（未列）。
   - 只有單一文法與單一 n/K=833（設定表已列，但沒有標為落差）。
2. **三層對應**：主指標 FAIL 最多否證一個子預測：「此設定下 w=3 不移動 sample-split 距離最低點」。
   - 機制：n/K 時鐘由閘門 4 測，不由主指標測。
   - 方向：CFG 與偏差泛化的訓練動態，沒有測到。
   - 用語：PREREG 本身沒寫題目死，但 53 號 §6 寫「(c)(d) 都不成立 → 放棄」，PREREG 沒有限縮這句。
3. **構造可行性**〔推導〕
   - 兩模型的 guided 差為 (1+w)δ_c − wδ_u，逐 t 正規化會抵銷常數倍率。
   - 若無條件分支的時鐘較慢、δ_u 相對可忽略，t\*(3)≈t\*(0)，主指標在構造上就落進 FAIL 帶。而這正是「CFG 純放大、不移時」的情形，也就是題目主張的另一半。
   - 20% 的位移門檻沒有任何推導。
   - 沒有「CFG 必然提早」的正控制。閘門 4 驗的是條件分支的時鐘，不是 CFG。
   - **提案**：合成雙時鐘敏感度控制。
     - 做法：用第 2 週已訓的 u833（類別 0 專用）當 p_c、K=1 模型當 p_u，離線組成 4p_c − 3p_u，在類別 0 輸入上算 t\*。
     - 判定：|log t\*_g − log t\*_c| ≥ log 1.1 才算主指標對時鐘差有敏感度；否則 (c) 的 FAIL 帶改記「未能測試」。
     - 成本：只做評估，約 1–2 GPU 小時〔推估〕。
     - 限制：兩個獨立網路的 δ 相關性比同網路 CFG 低，結果偏保守。
4. **是不是稻草人**：實作忠實，不是稻草人；但主指標挑的是題目裡最缺推導的子預測。
   - 第二探針：比較「正規化幅度」（已在算）在 K=6 與 K=1 負控制下 w=3 對 w=0 的配對差，用現有 eval npz，幾乎不花 GPU。
5. **建議修改**：見文末清單 (a)、(b)。
   - job 狀態：hier 訓練 26280 正在跑；CelebA eval 26294 排隊中，hier eval 26295 等相依；第 2 週還沒送；沒有任何結果。
   - **時限**：(b) 必須在 26295 產出第 1 週探索性主指標前 commit。PREREG 規定第 1 週的結果不得用來調整第 2 週。

## 2. inoculation-lambda（Λ）
1. **代理落差**
   - 只用 step 0 單點，但理論主張是 Σ_t Λ_t。k 步版列為次要（已列），但沒有寫成 FAIL 可歸因的落差。
   - **Λ 沒有正規化**（η=1 的原始內積），卻拿去預測「匹配 ID 下的漏出」（未列）〔推導〕。
     - 一階近似下，匹配 ID 時的漏出約正比於 Λ_τ/Λ_ID。
     - 原始 Λ 會把「防禦讓整體學得慢」也算進來。§7 的外部對照用的是比值 R_c，主判準卻沒有用。
   - τ 是固定留出回應的 log-prob，漏出則是生成時的行為率。REVIEW 建議 1 處理了「混入風格成分」，但 log-prob 到行為率的轉換沒有列出（未列）。
2. **三層對應**：FAIL（ρ<0.35）最多否證「step 0、未正規化的 Λ 對最終行為漏出的排序」。
   - 機制：一階轉移只由閘門 1 在單步上驗過，多步沒有測。
   - 方向：「統一的尺」沒有被否證。
   - 用語：54 號 §6 寫「判準 1 前半失敗 → 停」，PREREG 沒有限縮。
3. **構造可行性**
   - 可達的 ρ 上限是漏出本身在各 arm 間的信度。強防禦的 arm 多半漏出接近 0，會出現大量並列，壓低 Spearman。閘門 3 只在 1 個任務的 5 個 arm 上量 ICC，不等於 13 個 arm 的排序上限。
   - 閘門 1 只是單步正控制，多步下沒有正控制。
   - **提案 (i) 上限檢查**：每個任務算 seed 0 對 seed 1 漏出在 13 個 arm 上的 Spearman，經 Spearman-Brown 校正後跨任務合併。結果 < 0.7 時，PASS 在構造上不可達，記「未能測試」。0 GPU。
   - **提案 (ii) 地平線正控制**：Phase B 存訓練到 5% 步時的 LoRA，要求 Spearman(Λ, 實測 Δτ_5%) ≥ 0.8。
     - 不過：Λ 或 τ 本身有問題，屬實作層。
     - 過了但主判準 FAIL：失敗在地平線，或在 log-prob 到行為率的轉換。
     - 成本約 3–5 GPU 小時〔推估〕。
4. **是不是稻草人**：不是稻草人，但用的是最窄的版本。
   - 第二探針：在同一批 checkpoint 上算 Λ_τ/Λ_ID 比值版，或 k 步累積版。只算梯度、不重訓，約 2–5 GPU 小時。前提是 Phase B 有存 checkpoint。
5. **建議修改**：見文末清單 (a)、(b)。
   - job 狀態：Phase A 的 a1（26261）正在跑，a2–a4 等相依。
   - Phase B 還沒寫，所以所有修改都還能加。

## 4. multifidelity-attribution
1. **代理落差**
   - 用純量 α 而不是逐查詢 α_q（已列，S3）。
   - 用簡化版 Spell（已列）。
   - U 取自 G_V。45 號報告自己指出 grad-dot 的 LDS 只有 0.156，並建議改用便宜分數的 Gram 選方向（未列）。
   - 階段 0 只用 k=50，45 號的主張是 k=100–200（未列）。
   - **κ 與 κ_res 是按 Frobenius 能量加權**，LDS 卻是查詢等權（未列）。45 號引用附錄 C：前 1/4 的查詢佔 99.2% 的能量，所以 κ 的 STOP 條件實際上只由約 12 個查詢決定。
   - 主賣點之一的可靠度路線，在階段 0 STOP 時完全沒有被測到（未列）。
2. **三層對應**
   - STOP(gain) 與 FAIL 已有 S3 註記。
   - **STOP(κ_res/κ < 0.5) 寫成「殘差沒有可捕捉結構」**，但它只否證「G_V 的前 B 個向量捕捉不到殘差」，屬實作層。
   - STOP(便宜方法 ≥ 0.8) 屬於此設定內的方向層，合理。
3. **構造可行性**〔推導〕
   - 套用 45 號的近似式 cos² ≈ κ + (1−κ)ρ²，得 gain ≈ √(κ + (1−κ)ρ²) − max(√κ, ρ)。
   - κ=0.2 時，gain ≥ 0.04 需要 ρ ≳ 0.22；gain ≥ 0.08 需要 ρ 約落在 0.31–0.66。
   - 若 CIFAR 移除 1% 時，最佳便宜方法的 LDS ≲ 0.2〔憑記憶：MAGIC 論文裡 TRAK、EK-FAC 在此設定偏低〕，STOP(gain) 會在構造上必然發生，跟混合法的好壞無關。
   - 現有閘門只驗恆等式，沒有「有互補資訊時一定看得到增益」的正控制。
   - **提案**（全部離線，約 0 GPU）：
     - (i) 合成正控制：C_syn = Y + 雜訊，雜訊大小調到 LDS(C_syn) ≈ LDS(最佳便宜方法)，要求 gain ≥ 0.04；
     - (ii) 負控制：把 C 的樣本列隨機置換，要求 gain ≤ 0.01；
     - (iii) 與實作無關的 oracle：以 R 自己的前 B 個奇異向量當 U，算 κ_res/κ 與混合 LDS（規則 2）。
4. **是不是稻草人**：偏弱，審查已經承認。
   - 第二探針：α_q（0.5 收縮），加上用 C 的 Gram 選 U。用階段 0 現有資料離線算，0 GPU。
5. **建議修改**：見文末清單 (a)、(b)。
   - job 狀態：階段 0 的 26324–26327 已送出、排隊中。
   - **附註**：舊的 26301–26305（commit 8dd910a）也還在佇列裡，兩組重複。若兩組都跑完會有兩份階段 0 結果，有擇優風險，建議協調者取消其中一組。

## 5. rl-sparse-distill
1. **代理落差**
   - **只測 λ=1 這個端點**：rl_replace 在不一致的位置確定性地輸出 RL 的 greedy token（`gen_replace.py` 第 3 行），是 q\*_λ 家族裡多樣性最低的成員。題目的學生是 λ<1 的幾何混合取樣（未列）。
   - README 寫 rl_replace 是「學生上限」。這只對 pass@1 近似成立，對 pass@64 不成立（未列）。
   - 不一致位置固定用 greedy 不一致來判，題目另外還有 KL 閾值和熵 gate 兩種判法（未列）。
   - 判準 (ii) 不對稱：WiSE 有 8 個點構成前緣，混合法只有 1 個點（未列）。
   - 1.5B 配對、k=64、3000 token 上限（已列）。
2. **三層對應**
   - (i) FAIL 接近機制層：此配對、k=64 下，token 層級混合不保住 pass@k。
   - (ii) FAIL 只否證 λ=1 端點。
   - 方向（把混合目標蒸餾到前緣上）沒有測到。
   - **用語**：PREREG §3「任一不成立就停、不做蒸餾」、§4「FAIL（停，不做蒸餾）」、README「整題停」，都把實作層的 FAIL 寫成題目死。
3. **構造可行性**
   - 沒有硬上限。
   - (i) 在構造上偏容易：閘門 0(c) 已保證 RL 的 pass@64 至少比 base 低 2pp，而 rl_replace 大多數位置照 base 取樣。所以真正的檢驗在 (ii)。
   - **提案：前緣檢定力正控制**（0 GPU）。
     - 做法：「回應層級混合」是每次嘗試以機率 π 選 RL、否則選 base。用現有 base 與 RL 各 128 個樣本，離線精確算出它的 (pass@1, pass@64)。
     - 依據：1−(1−p)^64 對 p 是凹函數，所以這條曲線在族群上必然高於 base–RL 的弦〔推導〕。
     - 判定：在 rl_replace 的 pass@1 處，「混合 − 弦」的 1.25% 下界 > 0；不成立則 (ii) 記「未能測試（檢定力不足）」。
     - 附帶用途：這條曲線也是政策層級的前緣參照（44 號 §7.3）。
4. **是不是稻草人**：λ=1 是原作方法，不算稻草人，但它是家族裡對 pass@k 最不利的成員。
   - 第二探針：在 dev 400 題上，於不一致位置做 λ=0.5 的幾何混合取樣，每個配對約 5–8 GPU 小時〔推估：依 PREREG 的 rl_replace 成本按題數比例換算〕。
5. **建議修改**：見文末清單 (a)、(b)。
   - job 狀態：閘門 0 配對 A 的 26290–26293 排隊中；判準 1 還沒送。

## 6. chameleon-defense
1. **代理落差**
   - 只有單層 organism、基線是自訓的 8 層探測器、探測器用平均池化、沒有自適應攻擊者（已列，§2）。
   - 防禦只實作「擴增」一種，參數固定為 90% 能量、2 份、固定 C；INV 與 RND 只是次要指標（已列為次要，但沒有寫成 FAIL 可歸因的落差）。
   - 「逃避子空間跨概念共享」這個機制前提，沒有被單獨檢驗（未列）。
2. **三層對應**：閘門 2b 通過後的 FAIL，最多否證「這種擴增在 layer-12 organism 的 harm 上不轉移」，屬實作層。
   - 機制：沒有被單獨測到。
   - 方向：防禦、偵測器、自適應評估都沒有測到。
   - 用語：§4 已把結論限定在「只限第 12 層 organism」，是 6 題裡最好的；但仍寫成「停損證據」，§1 也寫與原本「任一成立就停」等價。
3. **構造可行性**
   - 已有：閘門 2b（基線餘量 ≥ 0.30）就是構造閘門，閘門 1 也有合成植入的正控制。
   - **缺的是真實激活上的正控制。提案：樣本內正控制。**
     - 做法：對 8 個 E 概念，每個概念 c 都用含 c 自己位移的子空間，訓練 c 的 ENS 與 ROB 探測器，在 c 的留出例、T0 觸發下計算 Δ_in。
     - 判定：8 概念平均 Δ_in ≥ 0.30，且乾淨正例的 TPR 稅 ≤ 0.05。
     - 解讀：不過，表示擴增在真實激活上無效，harm 的 FAIL 記為實作層；過了但 harm 仍 FAIL，失敗就在跨概念轉移，算機制層證據。
     - 再加一組留一法（子空間不含 c）可以把兩者分得更清楚。
     - 成本：用已快取的激活，< 0.5 GPU 小時〔推估〕。
4. **是不是稻草人**：合理，但是最小實作。
   - 第二探針：事先指定 INV（同一次分析就會算出）為唯一的第二探針，用同樣門檻，在 harm_test_extra（421 正、625 負）上確認，約 0.25 GPU 小時。
5. **建議修改**：見文末清單 (a)、(b)。
   - job 狀態：extract 26285 排隊中，analyze 26286 等相依。
   - **時限**：樣本內正控制的程式要在 26286 執行前寫好並 commit。
