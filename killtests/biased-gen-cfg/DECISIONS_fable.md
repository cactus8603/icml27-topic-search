# biased-gen-cfg 判準定案（Fable，2026-11-14，結果出來前凍結）

來源：Fable 子代理回報原文，由主對話轉存，未改寫。協調者已採用全部條文，包括 Fable 標出的三處偏離審查建議（項 1 組合方案、項 2 右設限、項 4 batch 85 與 K=1 當 n 時鐘）。

常數：log 1.1 = 0.0953，log 1.25 = 0.2231，log 0.8 = −0.2231。

## 條文 1：階層資料主指標的距離空間與 t 加權（取代 §1 第 2 行）

1. **距離空間改為 ε 空間。**
   - 每個分支先在 x0-hat 空間得到 p_b（CFG 為 `(1+w)p_c − w·p_u`），再轉成 `ε̂_b = (x_t − √ᾱ_t·p_b)/√(1−ᾱ_t)`。兩模型共用同一個 x_t。
   - 距離為逐樣本、把整個序列展平後的 `1−cos`，以 float64 計算。算式用 `0.5·‖â−b̂‖²`（â、b̂ 為單位向量），以免相消誤差。
   - 理由：53/56 的「分數距離」與 (a) CelebA 都是 ε 空間；ε 對 x0-hat 是線性的，CFG 在兩個空間等價，沒有額外自由度。
2. **逐 t 正規化。**
   - 對每個（模型對, 分支, t），先對兩份訓練輸入 S_i、S_j 取平均，再把這條跨 checkpoint 的曲線除以它自己的跨 checkpoint 平均。
   - 平均為 0 或非有限值時，該對記為 nan。
   - 理由：8 個 t 的 SNR 橫跨約 178 到 0.026，直接平均原始值會讓單一 t 主導 t*。
3. **t 遮罩只由 BP oracle 決定，不看任何 checkpoint。**
   - 輸入：測試區塊 7 的前 1000 筆，CPU `torch.Generator` seed 20261114，float64，依 t 網格順序加噪。
   - 計算：`g_t = mean_{樣本,位置} Σ_符號 (p_c^BP − p_u^BP)²`，使用真實根標籤。
   - 保留規則：保留 `g_t ≥ 0.01·max_t g_t` 的 t，等權平均。
   - 凍結：遮罩與 g_t 寫入 `configs/t_mask_hier.json`，在送評估 job 前 commit。之後所有評估（K=6、K=1、正控制）共用這份遮罩，不重算。
   - 理由：CFG 只在 p_c ≠ p_u 的 t 起作用。把條件曲線與 CFG 曲線相同的小 t 也等權納入，只會把主指標往 0 稀釋。
4. 主曲線 = 遮罩內各 t 正規化曲線的等權平均，再做 3 點置中平滑，取 argmin。主指標公式不變。
5. x0-hat 空間的 `pair_cos` 留在 npz，但 aggregate 不得用它算任何 t* 或做任何判定。
6. **CelebA (a) 不改**：用 ε 空間，t∈{50,100,150} 的原始平均。
   - 理由：(a) 是重現閘門，必須照原作 `compare_scores.py` 的量法；這三個 t 的 SNR 只差約 9 倍，不需要正規化。
   - 兩邊的距離空間一致，只有 t 的聚合方式不同，在此明文記錄。

## 條文 2：t* 邊界與「內部最低點」（涵蓋閘門 2、(b) 閘門、主指標）

**「有內部最低點」的定義**：用於 (a) 的偏差曲線與階層資料的各分支主曲線，兩項都要成立：
- 平滑後的 argmin 不在網格第一格或最後一格；
- argmin 之後的平滑曲線最大值 ≥ 1.10 × 最低值。

理由：71 格裡有 69 格是內部，平坦的雜訊曲線也幾乎一定「不在邊界」，所以要加上回升幅度，才算真的進入偏差期。

**(a) 重現閘門**
- 模型算「有效」的條件：偏差曲線有內部最低點，且 e_testloss_min 不在第一格。
- e_testloss_min 落在最後一格時仍算有效：以 5000 代入，並標記「右設限」。此時 log(e_loss/e_bias) 是真值的下界，對通過閘門而言是保守的。
- 有效模型 ≥ 5 個時，只用有效模型算 mean 與 SEM，判定式不變（mean > 2·SEM 且 > 0）。
- 無效模型 ≥ 2 個時，(a) 記「未能測試」，進入條文 5 的診斷順序。

**(b) 閘門（新增，第 1 週）**
- 條件分支主曲線（條文 1 的定義）在 3 個模型對中至少 2 對有內部最低點 → 通過。
- 否則記「未能測試（20000 epochs 內條件分支未進入偏差期）」，不判 FAIL，適用 3 個工作天的修復上限。
- 第 2 週 6 個 run 一起重評時，同一閘門改為 15 對中至少 10 對。

**(c) 主指標**
- 模型對算「有效」的條件：cond 與 cfg3 兩條主曲線都有內部最低點。
- 無效對數 > ⌊P/3⌋（15 對時 ≥ 6；6 對時 ≥ 3）時，(c) 記「未能測試（無偏差期或設限）」，不得判 FAIL，也不得判 PASS。
- 否則只用有效對計算點估計與 bootstrap，PASS 帶與 FAIL 帶門檻不變。
- 每一對的無效原因都要輸出：是 first、last 還是回升不足，以及是哪個分支。

## 條文 3：負控制改為 K=1 常數條件（取代閘門 5）

- 採用審查建議，廢除 n=70000 的負控制。理由：K=6 時 n=70000 每類約 11,667 筆，假設成立時本來就該有差，不是虛無控制；成本也超出上限。
- **規格**
  - n=5000，pdrop=0.1；所有樣本的條件標籤固定為 0，null 索引為 q。
  - 使用區塊 pick 0–5，seed = pick，與 K=6 的 run 同資料、同 seed。
  - 其餘超參數、checkpoint 排程與 20000 epochs 都與 K=6 相同。
  - 評估時條件輸入一律給 0，沿用同一份 t 遮罩，主指標定義完全相同。
- **run 數**：令 h 為第 1 週 3 個階層 run 實測的平均 GPU 小時。
  - h ≤ 2.0 → 跑 6 個（pick 0–5）。
  - h > 2.0 → 跑 4 個（pick 0–3），結果標「低檢定力」。
- **判準**（m1 = K=1 的主指標，m6 = K=6 的主指標）
  - m1 的 95% CI ⊂ (−0.0953, +0.0953) → 負控制通過，(c) 照原門檻判。
  - 否則負控制未過，(c) 的 PASS 改用對比量 `Δ = m6 − m1` 判定：
    - Δ 以區塊為單位做配對 bootstrap：同一次重抽同時算 m6 與 m1，K=6 只取與 K=1 相同的 pick。
    - Δ 平均 ≤ log 0.8，且 95% CI 上界 < 0，才算 PASS。
    - 不滿足時 (c) 不得記 PASS，歸入「其他組合，人工判讀」。FAIL 帶仍看 m6。
  - K=1 的無效對數 > ⌊P/3⌋ → 負控制記「未能測試」，(c) 的結果加註後交人工判讀。
- 理由：K=1 時 n/K = n，本題假設預測不應有差別。若仍有差，來源是「CFG 算術」加上「無條件分支只拿到 10% 的更新」。這是混淆因子，不一定是 bug，所以用 Δ 把它扣掉，而不是直接判定實作有錯。

## 條文 4：正控制規格（取代閘門 4）

三組模型都用 pick 0–N−1（N 同條文 3），都只在「各自區塊的類別 0 訓練輸入前 700 筆」上算 t*，都用 w=0、條文 1 的曲線定義與同一份 t 遮罩。

- **t*_c**：K=6 條件模型的條件分支，c=0。
- **t*_u833**：只用該區塊全部類別 0 樣本訓練的無條件模型（約 764–874 筆，正好是 K=6 模型看到的那批）。
  - 設定：pdrop=1.0，batch = 85，20000 epochs，其餘相同，seed = pick。
  - 理由：batch 85 讓每個 epoch 約 10 步、每步約 85 筆類別 0 樣本，與 K=6 模型中類別 0 得到的步數和每步樣本數相當。若沿用 batch 512，每個 epoch 只有 2 步，epoch 與步數兩種時鐘單位會混在一起。
- **t*_u5000**：條文 3 的 K=1 模型的條件分支。
  - 不另訓 pdrop=1.0 的 n=5000 模型。理由：K=1 時主幹的每一步都在學同一個無條件目標，等同 n=5000 的無條件模型，可省約 9–18 GPU 小時。
  - 不得用 K=6 模型的無條件分支當 n 時鐘。
- **統計量**：L_x = 各模型對 log t*_x 的平均，`λ = (L_c − L_u5000)/(L_u833 − L_u5000)`，以區塊為單位做聯合 bootstrap（2000 次）。
- **判定**
  - 分辨力：要求 `L_u5000 − L_u833 ≥ 0.4463`（即 2·log 1.25），且方向必須是 833 筆的模型較早。不滿足 → 記「控制無分辨力」，屬未能測試。
  - 通過：λ 的 95% CI 下界 ≥ 0.5，且 `|L_c − L_u833| ≤ 0.2231`。
  - 有分辨力但未通過 → 記「n/K 時鐘前提不成立」。這是題目層級的發現，不是管線錯誤：(c)(d) 仍照常判讀，但論文不得主張 n/K 時鐘，交使用者決定。
  - 任一組的無效對數 > ⌊P/3⌋ → 未能測試。

## 條文 5：建議 1、2、4

- **建議 1（(a) 的模型層級 bootstrap）：採用，只描述，不進判定。**
  - 重抽 6 個模型 2000 次，seed 0。
  - 每次對抽到的相異模型，只用同一次抽到的其他相異模型重算 e_bias，再依抽中次數加權取平均。
  - 相異模型少於 2 個的重抽跳過，並回報跳過次數。
- **建議 2（bootstrap 依 m_i·m_j 加權）：採用。**
  - 每次重抽的統計量 = Σ m_i·m_j·x_ij / Σ m_i·m_j，只計入有效對且 i ≠ j。分母為 0 的重抽跳過，並回報次數。
  - 點估計仍是有效對的等權平均。
  - 適用於 (c)、負控制、Δ、λ。
- **建議 4（(a) 失敗時的診斷順序）：採用，寫入 PREREG。** 只在 (a) 不過時執行，所有成本計入 3 個工作天與 115 GPU 小時的上限。
  1. 看形狀：test loss 與距離曲線有沒有內部最低點、loss 的量級。0 GPU。
  2. 用原作 `compare_scores.py -t 50/150` 評同一對 checkpoint，與 `eval_celeba.py` 的結果比對。上限 0.5 GPU 小時。
  3. 用原作 `run_Unet.py` 的 standard 模式訓 2 個模型，再用本包的 eval 評估。上限 2 GPU 小時。
  - 診斷結果只用來分類，不能把 (a) 改判為通過：
    - 原作模型過、本包模型不過 → 修 `train_celeba.py`，重訓 6 個模型，依凍結判準重判，限一次。
    - 原作模型也不過 → 記「可行性停損（現象在本設定不穩）」，交使用者決定。

## 條文 6：預算與順序

- 第 2 週順序：K=6 pick 3–5 → K=1 負控制 → 類別 0 專用模型 → 6 個 run 一起重評 → (d)。
- 送 (d) 之前，若「已用 GPU 小時 + 依 (d) 實測吞吐推估的用量」> 115 GPU 小時，先停下來回報使用者，不自行刪減。
- 第 1 週 3 個 run 的主指標只算探索性，不得用來調整第 2 週的任何設定。
