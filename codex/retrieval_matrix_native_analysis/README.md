# [codex] Native P0 analysis

This CPU workflow covers the seven scheduled jobs from three frozen producer
families: repaired SigLIP2 (`f3f787ee`), three repaired paired CLIC variants
(`5675ef59`), and released Swift Qwen3-VL-Reranker-2B/8B plus Jina m0
(`54f544ce`). It prepares a **REVIEW_REQUIRED** execution plan. Building or
validating that draft reads source and public data metadata only. It does not
read any production array, result, completion, raw call or model receipt.

The formal order is the original frozen mechanical script, a fresh
nonimplementer's original-array recomputation, the original family-specific
`make` and `admit` functions, and the user's final decision. Only a separately
approved plan, committed together with the reviewed source, can launch. The
builder never creates an approved plan or a model qualification. No GPU stage
is available.

`source-profiles.json` remains a source inventory, not an execution plan.
`build_plan.py` adds exact job/runtime/role contracts and seven full prospective
manifests under `dl/retrieval-matrix-native-analysis/manifests`. Each manifest
binds every model array, checkpoint state, completion, report and raw-call path.
Raw names derive from frozen public pair IDs and original call groups, never a
live output directory listing. Every later validation reconstructs these paths
and verifies the manifest SHA. The native MCQ manifest also identifies the
original invocation ledger that the original analyze command legitimately
appends; that ledger is recorded but is not falsely treated as immutable.

The metadata-only driver chooses the producer's exact CPU interpreter and
import paths. Before any model artifact is read, the worker checks every
frozen actual imported module and dependency payload, Python runtime and the
actual NumPy array binary SHA from a separately bound CPU probe. CUDA visibility is empty,
threads are fixed to one, and already initialized CUDA is rejected. Native MCQ
uses its original rerank environment; the retrieval families use their original
Torch 2.6/Transformers 4.51 import overlays plus the reviewed einops repair.
The original mechanical commands and recomputation runtime are recorded.

Every stage first commits READ_STARTED to this folder's preregistration and to
its own external durable journal. The reader/contracts are privately reused
only after matching immutable commit
`7b4855f5d1b7f6e6c1f3850b8a2a9e41b5ac82ed`. Neither the old analysis folder
nor its read log is changed. Its shared preregistration is compared only through
the immutable boundary, so root may append that separate authorized log.
PREPARE/append/COMMIT fsync ordering, directory fsync, hash chains, external
head/length binding and failure preservation remain the audited original
implementation. Truncated or rewritten logs, missing established anchors and
partial transactions fail closed. Failed attempts and outputs cannot be
silently overwritten or retried.

Roles distinguish evidenced authorship from conservative exclusion. Known
SigLIP2 implementation is attributed to matrix_runner by its frozen handoff;
both runtime repairs are attributed to p3_contract_review by parent's explicit
assignment, and native rerank to official_p0. Unknown paired base authors are
not invented from Git's display name. In addition, every job conservatively
excludes root, matrix_runner, public_data, official_p0 and p3_contract_review.
The new analysis implementer official_p0 and its synthetic-fixture implementer
native_full_fixtures are excluded as well. The actual mechanical actor and
central producers cannot act as the fresh independent reviewer. This role
exclusion is broader than the known-authorship table by design. A genuinely
fresh reviewer must explicitly declare nonimplementation; the original
reviewer identity and source/plan/model digests remain bound into receipts.

SigLIP2 retains COCO 5,000 images/25,010 texts and Flickr 1,000/5,000. Its
independent implementation retains Google FP32 full-matrix NumPy dot, default
quicksort ties and any-positive bidirectional R@1/5/10. No CORE caption split is
substituted. Paired CLIC retains SugarCrepe 7,511 image rows/15,022 captions and
SugarCrepe++ 4,757/14,271. Its six FP32 GPU scalar columns, batch1 dot/cosine
(eps=1e-6), strict ITT/TOT events and equal subset/group macros remain unchanged.
Independent CPU vectors must reproduce every strict GPU event; a tolerance
cannot repair different ties. The original arrays, final scalar receipt and
unchanged embedding receipt are all checked.

Native rerank retains 15,912 examples, 58,891 pairs, 9,425 images, eight subsets
and all three MCQ benchmarks. Jina COLA image-choice and Swift Qwen text-choice
keep their separate axes. Native scalar values remain lossless in FP64 storage
containers at32 original examples per chunk; inference dtype and original call
groups do not change. The independent original gate rechecks every checkpoint
fingerprint/batch hash, native raw scalar and cost ledger. A separate strict
per-example implementation also verifies every saved detail row and its order.
Its call budgets for
failed or unfinished requests are upper bounds; unrecorded kill duration and
peak remain unknown. Retrieval producers did not record a complete GPU call
ledger or peak; the workflow reports this gap rather than inventing one.

All family gates keep their own full benchmark/descriptor denominators and
require two distinct exact official benchmarks within the frozen1pp rule.
Missing-target qwen_native2/8 and Qwen8 Instruct remain ineligible. Original
independent JSON is preserved exactly because original `make` reopens arrays
and compares it. Extra analysis identity/roles/read receipts live in a separate
envelope. Original qualification JSON is also preserved; a passing receipt is
then exercised through its true original `admit` with the complete model spec.
Failed numeric qualification remains failed. No analysis state decides the
user's scientific verdict. Native-reranker scope cannot satisfy the old frozen
P3 reranker gate; downstream support needs a separate reviewed adapter.

CPU verification uses `test_contracts`, `test_workflow`, `test_full_flow` and
`test_pipeline`. The full-flow suite runs original `review -> make -> admit` with temporary synthetic
fixtures for all three families and both COLA axes. Tiny retrieval metadata and
synthetic published targets are explicitly disclosed; MCQ keeps complete
15,912/58,891 denominators. Scorers, native gate functions, checkpoint/hash
validation, original model specs and runtime references are not replaced.
The wrapper integration separately tests real reading and original admission,
replacing only synthetic metadata, the separately probed CPU environment and
mechanical subprocess transport. All synthetic records are removed on context
exit and are not P0 evidence.

After independent prelaunch review, root may copy the draft to a separate
approved plan, change only state/reviewed, and freeze the new source/approved
plan together. A later authorized operator can use `bash run.sh mechanical`,
then `independent --nonimplementer --accept-disclosed-protocol`, then `qualify`,
with explicit `--plan`, full `--freeze-commit`, `--job` and `--actor`. These are
future operations, not commands executed during this preparation.
