## P0 問題與驗收

驗證 3090 上依官方方法運行的 embedding 是否重現 CORE Table 2、Table 5，而後建立強基線矩陣。P0 六個模型為 CORE-Embed-2B／8B、Qwen3-VL-Embedding-2B／8B、GME-2B、VLM2Vec-V2.0。四個目標資料為 COCO 普通檢索、Flickr30K、完整 MCMR、NegBench COCO 否定檢索。其他 embedding 與重排器依報告 64 另增固定格，不能借名稱相近而不同的權重填格。

- 主重現量：COCO 與 Flickr 文字找圖 R@5、MCMR R@1／MRR、NegBench 否定 R@5。普通檢索另列雙向 R@5／10。
- 同一格的論文目標、查詢數、圖庫數、有效分母、正例對應與模型輸入須由原論文及官方釘版程式核對，寫入機械設定後才推論。報告 64 的轉錄值若與原始官方來源不一致，依原始來源事前修正並記錄理由。
- 報告 64 前段寫至少一個 benchmark、P0 章節寫至少兩欄；本執行採後者的較明確要求：每個模型至少兩個資料集欄位的絕對差不超過 1 個百分點。MCMR 的兩個指標不算兩個資料集。仍須呈現其餘已執行欄位，不挑對上的欄位隱藏偏差。
- 差異超過容差時按模板、指令、解析度、正規化、資料、分母及 official implementation 檢查；不按 test 分數搜尋超參數。保留原失敗結果與技術修訂原因。
- 技術成功、論文數字重現、獨立驗收為不同狀態。未通過 P0 不宣稱進入已驗收主矩陣。

## 版本凍結與輸入

每個執行批次在 GPU 研究推論前固定並 commit：官方程式 commit／檔案 SHA、模型 revision 及 payload checksum、processor／prompt／precision、資料清冊與逐檔 SHA、有效 query 列表與計分規則、batch／截斷及失敗處理、CPU 分析程式與主 target。批次 plan 連同本文件組成凍結契約。後續加入尚未執行的模型另存 plan，不覆寫已執行批次。

- 沒有訓練、量化、test 調參或用 gold 選候選。技術 smoke 只驗形狀、有限值、API 與資源，不判研究效果。
- 新版優先使用官方 implementation 與官方 instruction；舊 136 題的 image-only prompt、parser 或不一致 MCMR adapter 不直接當 P0 官方重現。
- 無效／空 query 依官方規則處理並明示分母，不按模型效果排除 query。
- 分模型單獨建立索引，不將 CORE／Qwen 的向量或候選冒充另一模型輸出。
- MCMR 保留官方商品圖片與文字；如原論文某模型採不同輸入，照官方方法分列並清楚標示。

## 開發、測試與統一矩陣

新物件連言面板保持 v1 規格及資料不變。dev-full 1,127 題／20,000 張；dev-small 252 題使用同一完整圖庫；test 1,122 題／20,000 張。自家方法僅能在 dev 開發。test 的固定基線量測可執行，自家方法在最終凍結後才評估一次。

統一重排主 K=100；K=50／200 各自分列。原論文若 K 不同，官方重現與統一矩陣適配分開。完整庫以 retriever 分數穩定排序，取 K 後由同一 reranker 重排；入池之外尾序沿 retriever，不丟掉無命中題。平手依原順位。ignore 在計分階段去除，不進模型或候選挑選，不補 K；分母仍是全部標註正例。另報 candidate recall 與最終 Recall@K，避免混用。

按資料集分開報告，不跨任務平均。保留所有固定基線，不因官方 test 排名挑一個當唯一對手。P3 所需兩個第一階段依 dev 結果事前固定，不能依 test 為自家方法挑有利對手。

MCMR pilot 的128題有自家方法曝光紀錄，全量官方基線仍可重現；新方法的確認評估另定未曝光範圍並揭露。NegBench 已做基線量測的1,000張亦保留曝光紀錄，停止用於自家方法選法。

## 成本、統計與獨立審查

記錄模型／索引載入、建庫、文字編碼、候選排序、cross、整體時間與 peak allocated／reserved VRAM。相同 K 不等於相同算力；離線整輪成本不當線上單題延遲。

P0 ±1 pp 是重現容差，無需把它解讀為顯著性。矩陣比較保留逐題輸出；後續方法效果的 bootstrap 單位、相關性／類別敏感度及多重比較另事前固定。正例互斥不自動推出完全獨立，不承諾新面板必能偵測 2 pp。

模型效果輸出與分析分離，讀取前先登記。由未實作對應主模組者獨立重算排名／指標與收據，root整合結果後交使用者判讀。
