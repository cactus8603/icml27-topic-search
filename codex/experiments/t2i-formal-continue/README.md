接受既有第一段 `26765` 與選格 `26802`。先核對兩作業的登記與完成狀態，再用 `26802` 印出的雜湊核對正式候選清單及作業表。待兩階段齊全，才依排程器算出的原始任務範圍接續 2a。遇到只有失敗、沒有成功重跑的索引時暫停。後段的 2b、任何灰區加碼與盲標先留待 2a 驗收。

控制程式、正式生成及成本程式各綁定 Git 版本。成本程式與依賴的生成程式直接讀提交的檔案內容，在原工作區路徑執行，供讀取同一份帳本和已產出的資料。現行工作樹若有成本程式新草稿，評估仍使用指定提交。送件則核對實際提交的取樣入口與原凍結版本一致。

每次以 Slurm 配置時間計入已發生的成本，包括失敗與重試，驗原 50 GPU 小時總上限及各階段的時間限制。群組確保有原計畫要求的 20 GiB 可用空間，並驗原題 35 GB 含固定資產的上限。當前共享磁碟低於協作通知線的情形已另由主代理告知。控制程式以作業鎖避免相同任務重複送出，並在送件後立即登記共享帳本。若作業送件無法確認，要先核對 Slurm 和帳本再續跑。
