## 面板、候選與對照

- 固定原 26601 凍結 `2daedf522c6d64b860277657d3067b61da3a0f2b`，使用已查驗的 8,191 張圖、136 個二物件合取查詢與原 118 群。繼續使用同一候選、合取標註與全池 AP 分母。所有圖檔、相同 manifest、模型設定與公開來源彙總收據重驗 SHA-256。保留原資料限制，包括小物件或未標註物件和未量的近似圖重複。
- 用原 CORE-EMB-2B 和 CS-CLIP 分別以整句對全池算 cosine 分數。同分按已升冪排列的影像 ID。基線使用 CORE 原前 50 名。另一臂逐名次先取 CORE、再取 CS-CLIP，略過已列入的圖，直到有 50 張。交換模型的次序或權重均不依這批資料調整。
- 兩臂使用同一個固定 CORE-RERANKER-2B 與原整句 `yes−no` logit 差，各自每查詢 50 對。先按原查詢、候選和 batch 順序算基線的 6,800 對，再只算另一臂需要的新對，共有的對重用同一分數。兩臂交叉編碼分數同分時按原 CORE 全池排名。各臂其餘圖的尾序為原 CORE 排序從中剔除該臂前 50 名，保留相對次序。兩臂的交叉編碼預算相同，另一臂額外使用一個全池 embedding。

## 量測與重現守門

- 主量是交錯臂相對基線的全池配對 mAP 增量。按固定 118 群重抽 10,000 次（seed `2026111591`），中央 95% 百分位區間。點估至少 +2 個百分點且下界大於零為 PASS，上界低於 +2 個百分點為 FAIL，其餘未定。Recall@50、全無正例查詢及上限差以描述統計提供。這一個固定池上的估計還需新池確認。
- 各臂保持名單成員與尾序，以已知標註把名單內正例排最前，得固定名單 mAP 上限。實測差等於兩個名單上限之差加上交錯臂縮小的排序差。名單上限也受尾序影響。用 Recall@50 與沒命中的查詢量區分候選准入，另外量只增加 CORE 名單深度至 K=25／50／100／200 時的標註上限和召回，無需多用交叉編碼。上限使用已知標註，涵蓋這一固定候選池。
- 交錯臂的額外交叉編碼前，重算原 CORE 基線的 mAP、固定前 50 名上限與 Recall@50，各須在已公開兩位小數值的 0.10 個百分點內，原無正例查詢數須為 31。原基線保留相同 batch 與精度，兩個模型均記錄分數距離在 `1e-6` 內的前 50 邊界題數。任一重現條件不符就停止，保留日誌排查。預檢驗資料、摘要雜湊、模型與合成案例，不做實際推論或讀取新排名。
