# GSM1k 暖機集的候選可判定率試驗

GSM1k `26669` 已做一次完整複驗。先前暖機集上的缺測集中於 Base 停止與解析問題。這個技術試驗只用原 250 題暖機題文，檢查能否準備可用於新金標研究的候選。只計停止、可解析數字及原驗證提示的輸入長度；正誤、原答、舊留出評分及政策參數皆不參與選擇。 [GSM1k 凍結版](../gsm1k-replication/PREREG.md)

- 固定題文、Base 模型、每題同一組兩個固定 seed、temperature 0.6、top-p 0.95 與原生 EOS。比較原始候選、維持原提示且 cap **768 → 1,536** 的 `cap1536`，以及 cap 仍為 **768**、在原系統提示追加要求簡短且只給一個 `\boxed{}` 數值結果的 `compact768`。兩個新條件各產生 500 筆 Base 候選，另與相同的 500 筆原 Oat 暖機候選組成面板。
- 按原規格只把 `stop` 且可用原 `boxed_number` 解析的候選計為可判定，無須讀標準答案。維持原中性雙映射及原驗證器的輸出配置。兩種驗證器各以 1,000 筆候選為分母，只有完整的兩份 A／B 提示均符合 **2,048 tokens** 的輸入上限才算可評。逐 Base／Oat 報結束原因與覆蓋，另以題為單位配對重抽 10,000 次（seed 202611151520），描述兩種新配置相對原 Base 的可判定率差。
- 選擇規則先看增加 cap，再看簡短提示。候選條件須在全部 1,000 筆中可判定 ≥85%，每一種驗證器的兩種提示均可用候選比例 ≥98%，才可用於另行凍結的新金標留出。兩種都未達則保留 Baseline 診斷、另選作答器或資料規格。此處只判讀暖機規格的技術可行性。

兩個新條件依序用單張 H200，估 **4–10 GPU 分鐘**，上限 30 分鐘。原模型及兩個評分 tokenizer 已緩存。只保留暖機候選、雜湊及計數，估 **<15 MiB**，真實顯存和耗時待量。
