# Attention gate 與高學習率穩定性深查

2026-11-14。優先檢查 NeurIPS 2025〈Gated Attention〉的公開 rebuttal、後續架構與 optimizer 消融、既有程式與可重現成本。以下的 pilot、門檻及成本是規劃估計，尚無新訓練結果。

## 判定

**廣義題目 NO-GO。** 換較強的 optimizer 改善無額外 residual gate 模型的高學習率穩定性，Qwen3.8 已給直接證據。用 attention forward 訊號觸發訓練期權重修正、保留原推論圖，Kimi K2 的 QK-Clip 已落地。更便宜的 QK norm、sandwich norm 和靜態 residual 縮放也是強對照。僅有「2×／3× 學習率跑得動」「loss spike 變少」或「gate 換另一個 optimizer」，缺少足夠的增量。 [Qwen3.8-Next §3.3](https://arxiv.org/html/2608.30320#S3.SS3) · [Kimi K2 §2.1](https://arxiv.org/html/2507.20534#S2.SS1) · [原論文 Table 2](https://arxiv.org/html/2505.06708#S3.SS2.SSS2)

**狹義題目先保留為低成本篩查，暫不立項。** 具體問題是 QK 已正規化、使用有競爭力的 optimizer 時，是否仍有「同一輸入下，某一步更新讓 attention 寫入 residual 的函數值突變」的失穩，而且直接限制造成突變的更新方向，比限制梯度大小、矩陣譜範數或單純降低實際更新幅度更快達到同一驗證 NLL。這個假說有明確介入方法，尚缺 headroom 與長訓證據。若只重現 stress test 下的門檻移動，仍維持 NO-GO。

## 起點與可歸因範圍

NeurIPS 2025 Oral〈Gated Attention〉用隨 query 輸入改變的 sigmoid，在 SDPA 輸出到 `W_O` 之前逐 head 或逐元素縮放。固定 28 層、1.7B、400B tokens 的 rebuttal 對照中，最高 LR 0.004 時 baseline／elementwise gate 的平均 PPL 為 **7.499／7.404**，最高 LR 0.008 時為 **8.941／7.425**。固定 0.004 而將 batch size 從 1,024 改 2,048 時，二者平均 PPL 為 **7.538／7.487**，兩種架構都較各自的 batch 1,024 略差。bMKL 接受高 LR 的證據，要求縮窄大 batch 的說法，評分 3 → 4。這組 28 層對照充分支持所測架構組合的高 LR 穩定性，且原論文以縮窄 elementwise 模型的 FFN 來對齊參數量，不能由這組估計只改 gate 一個元件的獨立效果。 [實際 rebuttal](https://openreview.net/forum?id=1b7whO4SfY&noteId=XIJTX5Mc3w) · [審稿人回覆](https://openreview.net/forum?id=1b7whO4SfY&noteId=heQ2eQxL17) · [Meta-review](https://openreview.net/forum?id=1b7whO4SfY&noteId=Zl7oqNR1FB) · [原論文 Table 2](https://arxiv.org/html/2505.06708#S3.SS2.SSS2)

同論文 48 層 1.7B、400B tokens、LR 0.008 下，baseline、sandwich norm、elementwise gate 的平均 PPL 是 **9.195、7.407、7.325**。sandwich norm 收回約 95.6% 的 PPL 差距 `(9.195−7.407)/(9.195−7.325)`，餘差 0.082 PPL。gate 在 LR 0.004 的 PPL 7.288 低於 LR 0.008 的 7.325，所以可用更高 LR 與最高品質並未在這個 PPL 指標上同步。48 層、1T tokens 則有 7.101 → 7.078 的小幅收益，顯示訓練長度與 batch 條件會改變相對結果。附錄 A.5 試過將 attention 和 FFN 的 residual 寫入 activation 截到 ±100 或 ±300，LR 0.008 仍有收斂問題。這個負結果針對 forward activation clipping，與 clipping 一步**造成的函數變化**是不同介入。以上是作者的平均 PPL，與其他資料集的 token NLL 不宜直接換算或相減。 [原論文 Table 2、附錄 A.5](https://arxiv.org/html/2505.06708)

### 只在訓練介入的強對照

- **QK-Clip 與 σReparam 已覆蓋低部署成本的大方向。** Kimi K2 從 forward 讀取 pre-softmax 最大 logit，超門檻時在更新後縮放 Q/K 投影權重，推論無額外 gate。中等 53B-A9B MoE 用 Muon 曾觀察到 logit >1,000，K2 正式訓練設門檻 100，作者報告 15.5T tokens 無 loss spike。另用 3B-A0.5B 模型、門檻 30 的對照測到 loss curve 幾乎不變。σReparam 在訓練期限制線性層譜範數，匯出能把重參數化直接折入權重。可保留的命題是 QK 已穩定時的 **post-SDPA attention 寫入變動**，需量測它與 pre-softmax logit 所預測的風險是否真的不同。 [Kimi K2 §2.1 與 Appendix D](https://arxiv.org/html/2507.20534) · [σReparam，ICML 2023](https://proceedings.mlr.press/v202/zhai23a.html)
- **矩陣更新控制已有強方法。** StableAdamW 把 AdaFactor 的 update clipping 加到 AdamW，以 tensor 級 `g²/v` 的 RMS 調整實際步長。ICML 2026 SPECTRA 做 update 的軟譜裁切，亦可裁切原始梯度，實驗涵蓋 124M–1.5B。它的 Table F.2 在 160M 模型測得 AdamW 每步 **200.7 ms → 238.3 ms（+18.7%）**，在 780M／820M 的增幅則是 **+1.6%／+2.1%**。Hyperball（2026-10 版）在 QK norm 架構固定矩陣權重與更新範數，130M 模型的 1B–128B token sweep 中，MuonH 優於 MuonW 的最佳 C4 loss。需要比同等實際更新大小的裁切與有競爭力的 Muon 類方法，不能把對未調 AdamW 的改善稱為方法收益。 [StableAdamW](https://arxiv.org/abs/2304.13013) · [SPECTRA §2、附錄 F.2](https://arxiv.org/html/2603.14315) · [SPECTRA 官方程式](https://github.com/mlolab/llm-spectral-clipping) · [Hyperball §3](https://arxiv.org/html/2606.16899#S3)
- **Pion 已直接展示只改 optimizer 可以替代一部分架構穩定控制。** 60M LLaMA 移除所有 norm 後，AdamW、Muon 梯度溢位，Pion 完成 9.6B token 訓練。正常架構 1.3B LLaMA 的 54B-token 實驗中，Pion 限制最大 attention logit 及 SwiGLU activation，但最終 val loss **2.7350**，介於 AdamW **2.7700** 與 Muon **2.7225**。這個例子也說明穩定指標改善不必然帶來最低 NLL。新方法應保留可競爭的常規排程品質，若長訓時仍有空間，再以其官方程式加強 optimizer 對照。 [Pion §3.1](https://arxiv.org/html/2605.12492#S3.SS1) · [官方實作](https://github.com/Sphere-AI-Lab/pion)
- **對 activation 子空間限制更新也有先例。** 2026-11 的 FRESCO 以 in-flight microbatch 的 activation 子空間投影更新，維持非同步 pipeline forward/backward 的一致性。它用的設定是非同步微批次的一致性，這裡的剩餘假說是同步訓練藉由限制一次更新在少數輸入上造成的 attention residual 改變，控制高 LR 下的品質與時間。單把 activation 投影加到 AdamW 也不是夠強的新意。 [FRESCO §2–3](https://arxiv.org/html/2611.11238#S3)

## 最小因果篩查與完成條件

**主問題。** 記固定輸入 $x$ 的 attention 寫入為 $A_\theta(x)=W_O\,\mathrm{SDPA}_{Q,K,V}(x)$。由同一 checkpoint 提出更新 $\Delta$，在重播中保持每層輸入 $x$ 相同，量 $\|A_{\theta+\Delta}(x)-A_\theta(x)\|_2/(\mathrm{RMS}(x)\sqrt d+\epsilon)$ 的 token 尾部分位數。分別替換 attention 及 MLP 的更新，再回放下一批 loss。固定每層輸入是為了隔離局部函數改變，另用全模型 next-batch NLL 檢查是否真的有下游影響。用小量固定探針測 p95/p99，並對照最大 QK logit、attention entropy、residual outliers、Adam 更新 RMS、梯度 norm 和 BF16／FP32 代理的可預測性。分析門檻在開發 seeds 上凍結，用新的 batch 與 seed 檢查。

1. **重現。** 約 63M 的 full causal GQA decoder，16 層、hidden 512、8 query heads／4 KV heads、SwiGLU 1,376、詞表 32,000、tied embeddings、seq 512、QK RMSNorm 開啟。固定資料 tokenizer、順序、packing、batch tokens、訓練步數和 BF16 設定。每種方法以同等搜索次數在 nominal schedule 選相近最佳 LR，再以各自最佳 LR 的 2–3 倍做 constant-LR stress。保留同一絕對 LR 的對照作機制分析，因不同 optimizer 的 LR 單位未必直接可比。第一輪對照是無 gate + AdamW、同 FFN 寬度 + headwise gate + AdamW、無 gate + StableAdamW、無 gate + Muon，以及無 gate + sandwich norm。所有可比臂同時報實際 FLOPs、步長大小與 wall-clock，parameter-matched 對照另列。 [小模型壓力測試及何時不能比 LR sensitivity](https://arxiv.org/html/2309.14322#A2) · [Optimizer benchmark 的調參與計時](https://arxiv.org/html/2509.01440)
2. **拆因果。** 可用 `2*sigmoid(0)=1` 初始化近似臂，讓共享參數、step-0 logits 與 ungated 相同。另用直接 sigmoid 的原版複核，並註明折入 `W_O` 的常數改變 optimizer 參數化。固定 per-head gain 可折入 `W_O`，是單純調小分支寫入的必要對照。若 gate 有正結果，在同一 checkpoint 回放正常 gate 與 `G(stopgrad(x))`，兩者 forward 相同，後者保留 gate 權重學習而移除從 gate 回到 block 輸入的梯度。另可用 forward 恆等、僅改 attention branch backward 的介入診斷更新路徑。Adam 對固定正倍率的梯度縮放大致可抵消，因一、二階矩共同縮放，須報實際更新與 $\epsilon$、weight decay，避免把梯度係數當作有效學習率。
3. **證明可改善。** 若開發資料上 tail 指標在強基線仍先於 loss spike，只限制 optimizer 所提議更新中造成探針寫入突變的分量。對單一探針 可先令 $u=z/\|z\|_2$，$z$ 是已算的 SDPA 輸出，已提議更新為 $D=\Delta W_O$。若 $\|Du\|_2>\tau$，改成 $D'=D-(1-\tau/\|Du\|_2)(Du)u^\top$。這是固定 $u$ 下使 $\|D'u\|_2\leq\tau$ 的最小 Frobenius 改動，在與 $u$ 正交的方向保留原步長。單一探針的結論限這個輸入方向，不能直接推論其他 token 或整個 block 已穩定。先在同一 checkpoint 分叉測 next-batch loss，與同 update RMS 的均勻縮小、同 spectral norm 的裁切和隨機方向比較。以週期性完整 attention replay 檢查 $D$ 的代理是否反映 Q/K/V 的聯動。若主要失效位置在 V 或跨層，單做 $W_O$ 的版本只能篩查。候選只在少數層、少數 step 啟動，量實際每步時間。若結果能轉移到留出的 token，再與已調 StableAdamW、Muon 或 MuonH、SPECTRA、QK-Clip 類 logit 控制及正規化架構比較。
4. **驗證真實收益。** 用兩個非 stress 的短／較長 token horizon、至少三個 paired seeds、另一個模型深寬比或資料集確認。主評估是達預先指定驗證 NLL 的 GPU 時間與失敗率，同時間的 NLL 也要報。計入 probe、optimizer、重啟和共同基線同規則的 profiling 開銷。另確認訓練匯出的權重直接走 ungated forward、無推論額外 kernel；gate-only 表達優勢要用標準 benchmark 留出測試，和訓練穩定性分開估計。比較含 gate 的 Pareto 前緣時按實測每步成本，不能假設 gate 記憶體流量與融合效益會按理論 FLOPs 線性反映。

### 預先設定的進退條件

- **先確認量測有效。** 2,048 步若只有零到一個自然 spike，計數本身不足以宣稱因果。優先查 gate/norm 實作、gradient clipping、BF16/FP32、warmup、資料順序和真正的失穩位置。應出現可在 paired seeds 重播的 loss 增幅、發散或多個 spike，並確認它在合理的 LR/batch 擾動下仍出現。無法建立這個失效時，記作小模型代理未成立。
- **空間不足則停。** QK norm + 經調參 Muon／StableAdamW 或可折入的靜態 gain 已在合理排程達同一品質與時間，或壓力訊號僅由已知的 QK logit／MLP outlier 主導時，關掉本題。若函數量測有訊號但 `ΔW_O·z` 不足，先以完整 replay 判斷是代理失真、位置不同還是缺少可改善空間。
- **有方法收益才升級。** 可暫用「同 NLL 時間至少縮短 5–10%，或同時間 NLL 至少改善 0.02 nats」作提案尺度，paired 結果需大於 seed 噪音，而且正常排程、等實際更新的對照與第二設定方向一致。這是待驗證的價值門檻。若收益只在極端 stress、只對未調 AdamW、被額外計算抵消，或延長訓練後像近作的 optimizer crossover 一樣消失，維持 NO-GO。

## 可重現性與成本

- Qiu 官方 [模型頁](https://huggingface.co/QwQZh/gated_attention) 有 baseline、headwise、elementwise 三組終點 checkpoint，對應模型檔各 **3.442／3.444／3.456 GB**。公開 config 是 28 層、hidden 2,048、16 Q／8 KV heads，baseline/headwise FFN 6,144，elementwise 5,504。headwise 是較乾淨的同 FFN 寬度對照。檔案清單有模型、tokenizer、模型程式，未見預訓練中途或 Adam moment state。因此可檢查終點與做短期續訓壓力測試，不能從這些權重還原原 rebuttal 的從頭訓練過程。原始 1.7B × 400B tokens 單一臂約 $6ND = 4.08\times10^{21}$ FLOPs，遠超初篩。 [官方 PyTorch attention 實作](https://github.com/qiuzh20/gated_attention) · [公開檔案列表](https://huggingface.co/QwQZh/gated_attention/tree/main)
- 現有 S2 的結果是 gate 改變 sink 保留的收益與 KV 策略評估，沒有 gate × optimizer 訓練軌跡。歷史紀錄寫到三組 Qiu 權重曾下載約 9.7 GiB。這次所在 workspace 的既定 sibling 路徑與模型快取未找到這三組，實際列出的模型目錄有 Qwen2.5 或 Qwen3 的其他 checkpoint。把舊紀錄當參考，先以公開 hub 檔案清單為可取得證據。 [S2 權重下載紀錄](../../reports/2026-11-14-06-s2-model-download.md) · [S2 既有證據](../../reports/2026-11-14-05-s2-data-audit.md) · [S2 結案原因](../../reports/2026-11-14-10-docs-update-s2-verdict.md)
- 可從 [SPECTRA 的 Llama 預訓練程式](https://github.com/mlolab/llm-spectral-clipping) 借 optimizer baseline 和資料／日誌管線，或從 [nanochat](https://github.com/karpathy/nanochat/blob/master/nanochat/gpt.py) 借簡潔的 GQA、RoPE、QK norm 與 SDPA 路徑。nanochat 現成還有 input-dependent value embedding gate、另乘 Q/K 1.2、其他殘差與 attention window 選項。先固定研究架構，停用與比較無關的可學 gate，避免把「無輸出 gate」誤寫成「整個模型沒 gate」。資料以固定 FineWeb shard 與文檔不重疊驗證 split，或同 tokenizer 的 C4 作第二資料來源。現成 speedrun 的多 GPU、編譯與 kernel 假設不直接套成單卡時間。 [FineWeb](https://huggingface.co/datasets/HuggingFaceFW/fineweb) · [C4](https://www.tensorflow.org/datasets/catalog/c4)
- 63M 設定的矩陣與 embeddings 約 **62.8M** 參數（忽略 norm 小項）。用 $6N$ 加因果 attention 的近似，seq 512 約 **0.40 GFLOP/token**，32,768 token/step × 2,048 steps = **67.1M tokens／臂**，12 臂約 **0.805B tokens、$3.24\times10^{17}$ FLOPs**。以單卡整體 **20k–80k token/s** 作規劃假設，純訓練約 **2.8–11.2 H200 GPU-hours**，評估、編譯、I/O、重播合計額外抓約 50%，約 **4–17 GPU-hours**。首輪 12 臂涵蓋少量 LR bracket 與 baseline 配對篩查，完整 factorial 或三 seed 確認另計。若進入 18 臂 × 4,096 步，僅短確認就約 **8.4–33.6 GPU-hours** 純訓練，長 horizon 應在證實 headroom 後才規劃。低利用率、非融合 optimizer、額外 forward 可能超出此估算。先量 100 個穩態 step 和實際 token/s 再更新預算。單純比較 8×H100 speedrun 的 81.2 秒會低估這套控制實驗的時間。 [NVIDIA H200 規格](https://resources.nvidia.com/en-us-gpu-resources/hpc-datasheet-sc23?xs=443995) · [SPECTRA 計時表](https://arxiv.org/html/2603.14315)

部署收益也需量級驗證。這個 63M 架構中，8 個 head 的 full linear headwise gate 每層僅多 $512\times8$ 權重，16 層共約 **0.066M**。elementwise gate 一層為 $512^2$，16 層共約 **4.19M**（同 FFN 寬度估算），額外線性層訓練 FLOPs 約 **6%**，不含 gate 中間 activation、融合或 allocator。若穩定且省時的參考點本來只需 headwise gate，省 gate 的推論計算可能太小。這種情況下，題目的價值須來自**訓練加速或在常規排程下仍穩的品質收益**，應以實測 Pareto 前緣裁決。
