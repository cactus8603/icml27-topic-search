# 公開判定重播與強驗證器的共同錯誤

在 1,869 筆已有兩個模型判定的候選答案中，Qwen3-32B 誤收 114 筆，其中 101 筆也獲 Qwen3-0.6B 接受。只抽查兩個模型分歧的案例，即使能逐筆揭露正確答案，也只會觀察到這 114 筆中的 13 筆。這支持在一致通過的案例仍保留抽查機率。資料評的是**答案是否正確**。正式數學證明的有效性需要另用專家標註驗證。 [原論文](https://arxiv.org/abs/2512.02304) · [公開逐筆資料](https://huggingface.co/datasets/Jacklu0831/llm-verification-raw)

## 資料與重算

公開資料的 `verifier_samples` 分組有 70,855 筆判定，來自 9 個資料集、152 個不同的資料集與題目組合。37 個模型都判過同樣的 1,915 筆候選答案。以資料集、題目、產生答案的模型、原始答案 SHA-256 聯合識別候選，驗證模型欄再識別每次判定，核對後沒有重複。所有候選都有發佈者提供的 `solver_correct`。原表 15,841 筆 `verifier_verdict` 為空，其中一些模型幾乎全無可解析判定。選一個 0.6B/32B 的同系列配對看信號，主分析保留兩個判定皆可解析的 1,869 筆，涵蓋 147 題、758 筆錯誤答案與 1,111 筆正確答案。固定資料版本為 `08f42e1ebdb4c69d09bd8c60761526d3f8aa6b8a`。 [資料字典](https://huggingface.co/datasets/Jacklu0831/llm-verification-raw) · [作者重現說明](https://github.com/agentic-learning-ai-lab/llm-verification#reproducing-the-paper-figures)

| 兩個模型的判定 | 答案錯誤 | 答案正確 | 合計 |
|---|---:|---:|---:|
| 都接受 | 101 | 976 | 1,077 |
| 0.6B 接受、32B 拒絕 | 262 | 23 | 285 |
| 0.6B 拒絕、32B 接受 | 13 | 101 | 114 |
| 都拒絕 | 382 | 11 | 393 |
| 合計 | 758 | 1,111 | 1,869 |

- **32B 單獨判定。** 錯誤答案誤收率為 114/758（15.0%），正確答案誤拒率為 34/1,111（3.1%）。0.6B 的誤收率為 363/758（47.9%）。以 147 個題目叢集為採樣單位，重抽 10,000 次的描述性 95% 百分位區間為 32B 誤收 11.2%–19.2%，0.6B 誤收 42.3%–53.9%。
- **32B 的錯誤集中在兩者同意的案例。** 101/114（88.6%，題目叢集重抽區間 83.2%–93.8%）。雙方一致接受的案例中，101/1,077（9.4%）的答案錯誤。只接受雙方都同意的答案，誤收降 **1.7 個百分點**到 13.3%，誤拒增加 **2.1 個百分點**到 5.1%。
- **換模型系列仍有共同誤收。** 將強模型換成 Llama-3.1-70B-Instruct，1,866 筆都可解析，其中 759 筆答案錯誤。70B 誤收 290 筆（38.2%），其中 205 筆（70.7%）也獲 0.6B 接受。這是另一次描述性對照，兩個較大模型的母體也因判定可解析性而略有不同。模型大小本身不能代表這個任務的判定品質。
- **題目層的變動有影響。** AIME 只涵蓋 15 題。矩陣乘法佔 32B 誤收的 51/114，整體誤收率有明確的資料組成限制。描述性區間反映題目重抽樣，沒有涵蓋選題偏差、可解析判定的選擇，以及模型選擇。

查詢可使用 DuckDB 或其他 Parquet 工具。從四個公開 `verifier_samples` 檔案讀取下列欄位，不需要推論。對每個欄位組合的八格計數為後續成本與抽查分配推演的輸入。

```sql
WITH paired AS (
    SELECT
        dataset,
        question,
        solver_model,
        solver_output_sha256,
        any_value(solver_correct) AS correct,
        max(verifier_verdict::INTEGER) FILTER (
            WHERE verifier_model = 'Qwen/Qwen3-0.6B'
        ) AS weak_accept,
        max(verifier_verdict::INTEGER) FILTER (
            WHERE verifier_model = 'Qwen/Qwen3-32B'
        ) AS strong_accept
    FROM read_parquet('data/verifier_samples/*.parquet')
    GROUP BY dataset, question, solver_model, solver_output_sha256
)
SELECT weak_accept, strong_accept, correct, count(*) AS candidates
FROM paired
WHERE weak_accept IS NOT NULL AND strong_accept IS NOT NULL
GROUP BY weak_accept, strong_accept, correct
ORDER BY weak_accept, strong_accept, correct;
```

## 如何用於第一輪驗證

### 強模型有多少額外訊號

固定便宜模型的接受／拒絕決策，分別在其接受與拒絕的案例中，估計該決定其實錯了的機率。以題目為單位留一交叉驗證，每次用其他題目估錯誤率，加半個正例和半個負例平滑。比較只知道便宜模型的判定與另外知道強模型的判定。用同一批留出案例量平方殘差，避免以全資料估分層錯誤率後再回頭宣稱降低方差。

| 配對的第二個模型 | 評估範圍 | 原先選接受時的誤收估計，Brier score | 原先選拒絕時的誤拒估計，Brier score |
|---|---|---:|---:|
| Qwen3-32B | 9 個資料集 | 0.1968 → 0.0833（−57.7%） | 0.1750 → 0.0445（−74.6%） |
| Qwen3-32B | GSM8K + AIME | 0.1556 → 0.0328（−79.0%） | 0.1276 → 0.0231（−81.9%） |
| Llama-3.1-70B-Instruct | 9 個資料集 | 0.1971 → 0.1508（−23.5%） | 0.1747 → 0.1285（−26.4%） |
| Llama-3.1-70B-Instruct | GSM8K + AIME | 0.1565 → 0.1007（−35.7%） | 0.1271 → 0.1186（−6.7%） |

這是將已發布的兩筆判定都當作可觀測、可用大量標註估錯誤分層時的訊號檢查。式中的誤差是在固定弱模型動作下的風險分子，與整體 FPR、FNR 的分母分開。真實線上流程只會看到 sparse gold，且觸發強模型有額外成本。上表給的是可用於設計實驗的殘差證據，完整的兩個錯誤率約束還需各自估計對應的類別分母，並在同一預算下重播。

可用一個明示假設的敏感度計算做第一道成本檢查。令 gold 一次成本為 1，總預算每題 0.1，便宜模型成本是共同常數。假設原本均勻抽查機率為 0.1，新方案每題都額外詢問強模型、其相對成本為 $c$，故均勻抽查率降為 $0.1-c$。二者都以各自的預測做 control variate 時，由隨機抽查引入的條件方差項為平均平方殘差乘 $(1-p)/p$。把表中誤收／誤拒兩個殘差比分別代入，Qwen3-32B 在整組資料最多只能花約 **0.055／0.073** 個 gold 成本，才能各自不增加這個方差項。Llama-3.1-70B-Instruct 為 **0.022／0.024**。這個推演假設每題均勻抽查、固定成本及已有殘差估計，未涵蓋自適應查詢、冷啟動與變動成本，也未量到真實的專家工時。它顯示「昂貴判定值不值得查」隨模型配對差很多。 [Active Multiple-Prediction-Powered Inference §3](https://arxiv.org/html/2605.08429#S3)

### 以完整訓練標註估算接受／拒絕政策的潛力

同一批資料另做了有限狀態線性規劃。以便宜模型的二元判定 $W$ 選擇接受、拒絕、直接用 gold 判決，或買強模型的二元判定 $S$。允許買強模型時，得到 $(W,S)$ 後可接受、拒絕或交給 gold。每個分支可隨機混合。最小化 `0.1 × 強判定比率 + 1 × 專家比率`，在訓練折同時壓住誤收、誤拒各 9%。便宜模型是兩邊共同成本，兩邊都可直接問 gold。假設 gold 即時返回，且會修正**當下**的判決。

實作為線性規劃。第一層 $u_{w,a}$ 對每個 $w$ 加總為一。第二層的無條件權重 $v_{w,s,a}$ 對每個 $(w,s)$ 加總為第一層付費分支 $u_{w,\mathrm{strong}}$。對 $P(W=w,Y=y)$、$P(W=w,S=s,Y=y)$ 加權，分別以錯誤答案和正確答案的筆數作 FA、FR 的分母。維持各資料集內以題目分組的五折，依排序後的題目用 seed 20261114 洗牌後交錯分到各折。在四折的**全部** gold 上求最省的混合政策，測試折上的判決以混合權重計算期望而非再抽一次亂數。合併各折時依各自的風險分母重算。

| 強模型配對、範圍 | 便宜模型＋直接 gold 平均成本 | 可加強模型的平均成本 | 留出測試 FA／FR（便宜＋gold → 可加強模型） |
|---|---:|---:|---:|
| Qwen3-32B，全部 147 題 | 0.619 | 0.285 | 9.05%／9.31% → 9.29%／9.19% |
| Qwen3-32B，GSM8K＋AIME 37 題 | 0.522 | 0.061 | 9.40%／8.55% → 9.20%／8.61% |
| Llama-3.1-70B-Instruct，全部 147 題 | 0.619 | 0.543 | 9.05%／9.32% → 9.05%／9.29% |
| Llama-3.1-70B-Instruct，GSM8K＋AIME 37 題 | 0.520 | 0.381 | 9.40%／8.54% → 9.67%／8.41% |

這個對照證實特定模型配對的額外訊號**可能改變決策成本**。Qwen3-32B 的整組平均成本低約 54%，換模型後約 12%。此處的金標訓練成本沒有計入，固定的價格比也是假設，測試上的錯誤率只是點估計。五折用完大量金標的政策能否由少量機率抽查學到，以及有沒有比「固定混合政策＋均勻探索」更好，仍需測。尤其 37 題的子集只能作方向參考。這是第一週可用的機會上限，後續應扣掉探測及校準成本，拿更強的金標路由、相同兩個 verifier 的固定級聯和同資訊的既有方法當基線。

### 正式評估

這份公開資料足以測試重播、遮住金標、線上更新、模型同意時仍抽查等流程。只有二元 verdict，做不了連續 confidence 門檻的比較。部署版須對無法解析的模型輸出明確設置轉人工或棄權的動作，並算入成本。先用這份資料排查重播與估計器，再用按題目分組的專家標註證明集，實際量兩個模型的連續分數與成本。

在一致接受群保留非零抽查率，才能從部署資料量到共同誤收。比較等成本的均勻抽查、只按便宜模型信心分配、用強模型輔助的抽查。純粹偏向分歧案例可作為對照，且要揭露其可觀測範圍。對兩個模型一致接受但沒有金標的子群，除非另外假設模型錯誤率，無法保證真實誤收很低。首輪若只看到強模型降低離線誤收，仍需確認它能在**同預算、按題目獨立切分的重播**裡改善決策。 [數學證明 VerifierBench](https://huggingface.co/datasets/internlm/AdvancedMathBench) · [Selective Auditing](https://arxiv.org/html/2610.31662v1#S7)
